# フロントエンド

コマンドラインから叩くための実装。**実行系（コア）とは別に作る。**

コアは組み込み用の部品で、ファイルも端末も扱わない（[runtime/embedding.md](runtime/embedding.md)）。
しかもコアは手を入れて使う雛形なので（[skeleton.md](skeleton.md)）、
このフロントエンドも「雛形をそのまま使ったときの参考実装」という位置づけになる。
その外側でファイルを読み、コアを呼び、返ってきた診断を端末向けに整形するのがフロントエンドの役目。

```
       shark コマンド（この文書）
        ├── ファイルを読む
        ├── コアに文字列として渡す        load()
        ├── 診断を端末の形に整形して出す
        ├── 少しずつ動かす                step()
        └── バイトコードとして保存する     build（下の「単一バイナリにする」）
                    ↓
              実行系（コア）
```

学習用ゲーム本体も、同じようにコアを呼ぶ別のフロントエンドにあたる。
コアはどちらからも同じように使える。

## コマンド

```
shark run main.shk        # 実行
shark check main.shk      # 型検査だけ
shark build main.shk      # 実行装置ごと1つにまとめる（→ ./main。どこでも動く）
shark build --bytecode main.shk   # バイトコードを .shkc に保存するだけ
shark run main.shkc       # 保存したバイトコードを実行
shark test                # テスト（library/test.md）
shark explain E0102       # エラーの詳しい説明
shark fmt main.shk        # 整形
```

- `run` は `step()` を上限なしで回し続ける。ゲームと違い、区切る必要がない
- `--lang ja` `--lang en` で診断の言語を選ぶ
- `--strict` で警告をエラーとして扱う
- `--memory <MB>` で、**動かすときに**使ってよいメモリの量を渡す（`0` で上限なし）。
  コアはこれを超えたところで実行時エラーにする。
  型検査までに使う量は数えない（[runtime/memory.md](runtime/memory.md)）
- `--jit off` で実行時コンパイルを切り、仮想マシンだけで動かす
  （[runtime/execution.md](runtime/execution.md)）。**どちらでも結果は同じ**なので、
  違いが出たときの切り分けと、速さを比べるためのもの
- `run` に渡されたファイルがバイトコードだった場合は、型検査をせずそのまま動かす

## 単一バイナリにする（build）

`shark build` は、型検査を通したプログラムをバイトコードにして
（[runtime/bytecode.md](runtime/bytecode.md)）、
**バイトコードだけを動かす実行装置**のうしろに埋め、1つの実行ファイルにする。

```
       shark build main.shk
        ├── ソースを読む → コアに渡す      load()
        ├── バイトコードにする             bytecode_write()
        ├── 実行装置（sharkvm）を探して読む
        └── うしろに足して、実行できる形で書き出す
```

- 実行装置は**別の実行ファイル**として先に作っておく（`make sharkvm`）。
  探す順は `--runtime <path>` → 環境変数 `SHARK_RUNTIME` →
  `shark` 自身と同じ場所 → いまいる場所
- 渡されたファイルが実行装置かどうかは、その中の目印を見て確かめる。
  違うものを土台にしようとしたら、作らずに知らせる
- **作るときに決まるもの**は、メモリの上限（`--memory`）と診断の言語（`--lang`）。
  できたファイルは引数をぜんぶプログラムに渡すので、あとから渡す口がない
- 保存したバイトコードを動かすとき、フロントエンドは**型検査を持つ必要がない**。
  実行装置は `Runtime`（[runtime/bytecode.md](runtime/bytecode.md)）を呼ぶだけの、
  `shark` より小さいフロントエンドになる

## 診断の整形

コアから返る `Diagnostic` を、端末で読みやすい形にする
（[runtime/diagnostics.md](runtime/diagnostics.md)）。

```
error[E0102]: int と float は足せません
  --> main.shk:3:13
  3 | var total = count + price;
    |             ----- int
    |                     ----- float
  直し方: float(count) + price と書くと足せます
```

- 行の中身を出せるのは、ファイルを持っているフロントエンドだけ。コアは位置しか返さない
- 色を付けるかどうか、下線をどの記号で引くかは、ここで決める
- ゲーム側は同じデータから別の見た目を作る

## 標準ライブラリの入れ方

フロントエンドは、その環境で用意できるモジュールを**全部**コアに登録する
（[library/overview.md](library/overview.md)）。
デスクトップなら `file` `net` `os` まで入る。

学習用ゲームは、段階に応じて絞る。同じコアで、使えるモジュールだけが変わる。

## 編集環境の支援（構想）

ここは、まだ仕様として固めていない。

### 自動 import

パッケージの配布を持たないぶん（[runtime/module.md](runtime/module.md)）、
`import` は手で並べることになる。ここを埋める。

- `time.now()` と打った時点で `import std.time;` を先頭に足す
- 使わなくなった `import` に印を付ける
- 同じディレクトリの `.shk` は候補として出す

標準ライブラリはモジュール名が短く名前空間も重ならないので、
どの `import` を足せばよいかは機械的に決まる。

### そのほか

| 機能 | 内容 |
|---|---|
| 補完 | 型が厳格なので、変数の後ろに出せる候補は正確に決まる |
| エラー表示 | `shark check` の出力をそのまま編集画面に出す |
| 整形 | 書き方を1つに固める。設定は持たない |
| 定義へ移動 | オーバーロードは引数の型で選び分ける |

## 決めていないこと

- 言語サーバとして常駐させるか、`shark` を都度呼ぶか
- 整形の細かい規則（字下げ幅、1行の長さ）
- ツールをコアと同梱で配るか、別に配るか
