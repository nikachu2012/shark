# 移植層

「外部依存が少なく、容易に多くのプラットフォームに移植することができる」を守るための決めごと。

## 方針

処理系のほとんどはプラットフォームに依存しない部分で書き、
OS に頼る部分だけを**移植層**という薄い境界に閉じ込める。
新しい環境に移すときは、移植層だけを書けばよい状態にする。

```
      Shark のプログラム
 ─────────────────────────
   仮想マシン・型検査・標準ライブラリ   ← どこでも同じ
 ─────────────────────────
              移植層                  ← ここだけ書き換える
 ─────────────────────────
        OS / ハードウェア
```

雛形では、移植層は `platform/` の下に**ターゲット環境ごとに1つ**配置する
（[../skeleton.md](../skeleton.md)）。
新しいプラットフォームへ移植する際は、モジュールを追加して差し替える。

## 移植層に求めるもの

新しいプラットフォームに移すとき、次だけを用意すれば動くこととする。

### 必須

| 分類 | 内容 |
|---|---|
| メモリ | 確保・解放（できないときは失敗を返す。使いすぎの見張りはコアが行う → [memory.md](memory.md)） |
| 時間 | 現在時刻、単調増加する時刻、指定時間の待機 |
| 標準入出力 | 読み・書き |
| 終了 | 終了コードを返して終わる |

### 任意（無ければその機能が使えないだけ）

| 分類 | 内容 |
|---|---|
| ファイル | 開く・読む・書く・一覧 |
| ネットワーク | ソケット。**待ちっぱなしにならない形**であること（下） |
| スレッド | 生成、待ち合わせ、排他 |
| 画面 | サーフェス描画バッファの転送、入力イベントの通知。`std.ui` が使用。OS ウィンドウまたはゲーム機ディスプレイ → [../library/ui.md](../library/ui.md) |
| 文字入力 | 日本語入力（IME）、テキスト選択範囲、クリップボード連携。`std.ui` が使用 → [../library/ui.md](../library/ui.md) |
| フォント描画 | プラットフォームがフォントラスタライズを提供する場合（ブラウザ等）、1文字ごとのアルファマスクを返却。`std.ui` が使用。未実装時は内蔵 5×7 ASCII または FreeType を使用 → [../library/ui.md](../library/ui.md) |
| 動的コード | 実行時コンパイル用の実行可能メモリ |
| 乱数のもと | 真の乱数（機器の雑音）と、OS の暗号用乱数。`std.crypto` が使う → [../library/crypto.md](../library/crypto.md) |

無い機能を使おうとしたときは、`Result` の失敗として返す。落とさない。

画面表示機能のみは例外であり、利用不可でもエラーとはしない。`std.ui` は**オフスクリーンバッファ**に同様に描画する
（可視状態は `ui.visible()` で判定可能 → [../library/ui.md](../library/ui.md)）。
メモリ上での描画処理自体は全環境で共通して実行可能であり、エラーにするとコードの分岐が過剰に増えるため。

### ノンブロッキング I/O の徹底

コアは一定ステップごとに実行を区切ってホストに制御を戻す（[embedding.md](embedding.md)）。
その途中で移植層がブロックすると、ホストゲーム全体がフリーズする。
そのため、待機を伴う処理には以下のいずれかを要求する。

- ブロックせず「即座に処理可能な分」のみを返すノンブロッキング形式
- タイムアウトを指定可能な形式（タイムアウト時間はコアのタイムスライス周期より短いこと）

無制限に完了を待機し続けるブロッキング呼び出しは使用しない。
取り消し（[concurrency.md](concurrency.md)）もこの前提の上に成り立っている。

## 依存してよいもの

- 実装は C++（[../skeleton.md](../skeleton.md)）
- 標準ライブラリは、どの機種にもある薄い範囲に限る
- **例外と RTTI は使わない**。ゲーム機では無効化されることが多いため
- それ以外の外部ライブラリには依存しない（画像・GUI ツールキットを含む）
- **例外はフォントだけ。**日本語などの字形は数百 KB になるので、
  `std.ui` は FreeType があれば使う。**任意**で、無ければ内蔵の 5×7（ASCII）だけになる
  （[../library/ui.md](../library/ui.md)）

これは思想の「外部依存が少なく」を厳しく守るための線引き。
そのぶん自前で書く部分は増えるが、移植先で詰まらないことを優先する。

## 想定する移植先

第一の移植先は**ゲーム機**。学習用ゲームの一部として動く（[embedding.md](embedding.md)）。
次いでデスクトップ（Windows / macOS / Linux）、モバイル、ブラウザ（WebAssembly）、
組み込み（ファイルも画面も無い環境を含む）。

ゲーム機ではファイルもネットワークも自由に使えないことがあり、
スレッドの扱いも機種ごとに違う。そのため必須項目には**ファイルもスレッドも入れていない**。

### ホストが間に立つ場合

ゲームに組み込むときは、移植層をゲーム本体（またはそのフレームワーク）が用意する。
コアは OS を直接触らず、渡された機能だけを使う。
そのぶん、ゲーム機ごとの違いはゲーム本体の側で吸収される。

## 数値の一致

同じプログラムはどのプラットフォームでも同じ結果を出す。

- `int` は常に 64 ビット（[../types/primitive.md](../types/primitive.md)）
- `float` は IEEE 754 の倍精度、丸め方は最近接偶数で固定
- `map` の反復順は挿入順で固定
