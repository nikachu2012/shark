# モジュール

## 1ファイル＝1モジュール

ファイルの名前がそのままモジュール名になる。`util.shk` は `util`。

## 取り込み

```shark
import std.time;          // 標準ライブラリ
import ./util;            // 同じ場所の util.shk
import ../lib/parser;     // 相対パス
import ./util as u;       // 別名を付ける
```

- `import` はファイルの先頭にまとめて書く
- 取り込んだものは `time.now()` のようにモジュール名を付けて使う
- 名前を直接持ち込む形（`from ... import ...`）は**用意しない**。
  どこから来た名前か読んで分かる状態を保つため

## 公開と非公開

トップレベルの宣言は既定で非公開。`public` を付けたものだけが外から見える。

```shark
// util.shk
public func add(a: int, b: int) -> int { return a + b; }
func helper() -> int { return 1; }          // 外からは使えない

public class Fish { }
public const VERSION = "1.0";
```

クラスのメンバの可視性と同じ規則（[../types/class.md](../types/class.md)）。

## 探し方

1. `./` `../` で始まる場合は、書いたファイルからの相対パス
2. それ以外は、標準ライブラリ → プロジェクトの `lib/` → 環境変数 `SHARK_PATH` の順

## 循環

A が B を、B が A を取り込む形はエラーにする。
初期化の順番が決められないため。

## 初期化

トップレベルの `var` / `const` は、モジュールが最初に取り込まれたときに一度だけ、
書いた順に初期化される。依存の深いモジュールから先に初期化される。

## パッケージ

**持たない。**ディレクトリをそのまま置き、相対パスで取り込む。

配布の仕組み（設定ファイル、バージョン解決、ネットワーク越しの取得）は、
言語より先に大きくなりやすい。まずは無しで進める。

たくさんの `import` を書く手間は、処理系ではなく編集環境の側で減らす
（[../frontend.md](../frontend.md)）。
