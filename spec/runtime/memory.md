# メモリと値の扱い

「全ての代入はデータコピーとし、参照渡しは別の方法で行えるようにする」を実現する。

## 値セマンティクス

代入・引数渡し・戻り値は、すべて中身のコピー。

```shark
var a = [1, 2, 3];
var b = a;
b.push(4);
print(a.len());     // 3
```

## 実装：書き込み時コピー

毎回まるごとコピーすると遅いので、実装は次のようにする。

- 代入時は実体を共有し、参照数を1つ増やすだけ（コピーしない）
- どちらかが**書き込もうとした時**に、参照数が2以上ならそこで初めて複製する
- 参照数が1なら、そのまま書き換える

見た目の動きは常に「代入した瞬間にコピーした」のと同じになる。

## 寿命の管理：参照カウント

値が要らなくなった判定は参照カウントで行う。ガベージコレクタは持たない。

理由は、**循環参照が原理的に作れない**から。
代入がコピーである以上、「自分の中に自分を入れる」ことはできない。

```shark
class Node { var next: Node?; }

var a = Node();
var b = Node();
a.next = b;      // b のコピーが入る
b.next = a;      // a のコピーが入る。循環にはならない
```

これにより、追跡型のごみ集めが不要になり、実装が小さくなり、
停止時間が読めるようになる（GUI に有利）。

## ref

同じ実体を触りたいときだけ `ref` を使う。

```shark
func add_one(ref xs: list<int>) -> void {
  xs.push(1);
}

var xs = [1];
add_one(ref xs);    // 呼ぶ側にも ref と書く
print(xs.len());    // 2
```

### ref の規則

- 引数にだけ書ける。`var r = ref x;` のように変数に取っておくことはできない
- 関数から `ref` を返せない
- クラスのメンバに `ref` は持てない
- `ref` を受け取った関数が返るまで、元の変数は生きていることが保証される
- `ref` はタスクの境界を越えられない（[concurrency.md](concurrency.md)）

つまり `ref` は「呼んでいる間だけの借用」。
これにより、無効な参照が残ることが構造上ありえなくなる。

### なぜ呼ぶ側にも書くのか

呼び出しを見ただけで「この変数は書き換わるかもしれない」と分かるようにするため。

## ハンドル型

実体を1つしか持てないもの（OS の資源、走っているタスク、待ち行列）は**ハンドル型**とする。
ハンドル型はコピーしても**同じ実体を指す**。値セマンティクスの唯一の例外。

| 型 | 指しているもの |
|---|---|
| `File` | 開いているファイル |
| `Conn` `Listener` | 通信の口 |
| `Task<T>` | 走っているタスク |
| `channel<T>` | 待ち行列 |

```shark
var ch = channel<int>();
task producer(ch);       // コピーが渡るが、同じ待ち行列を指す
var v = ch.recv();       // 相手が送ったものが届く
```

- ハンドル型は標準ライブラリだけが提供する。ユーザーが `class` で作ることはできない
- 閉じる操作（`close()`）は何度呼んでもよい。2度目以降は何もしない
- 最後のコピーが要らなくなった時点で、実体も片付けられる

「コピーしたのに元にも影響する」のはここだけなので、
どれがハンドル型かは標準ライブラリの説明に必ず書く。

## 使いすぎたとき

**プログラムを動かすときに使ってよいメモリの量を決めておき、
超えたら実行時エラーで止める。**

ゲーム機では、確保に失敗してからできることが少ない。
言語も例外を持たないので（[error.md](error.md)）、
確保の失敗をその場で受け止めて書き換える道も無い。
そこで「失敗してから対処する」のではなく、
**先に上限を決めて、超えたところで止める**。

上限は**組み込む側が決める**（[embedding.md](embedding.md)）。

### 何を数えるか

上限が見るのは、**仮想マシンがプログラムを動かしている間に作るもの**だけ。

| 数える | 数えない |
|---|---|
| 実行中に作った値（文字列・配列・連想配列・クラスの実体…） | 構文木 |
| タスクの値スタック | バイトコードと定数 |
| 標準ライブラリが実行中に作るもの | 型の表、診断、モジュールのソース |

読み込み（字句解析〜バイトコード生成）で作るものを外すのは、
そこはソースの大きさで決まる**一度きり**の量だからで、
プレイヤーの書き方しだいで際限なく増えるのは実行中の側だけだから。
組み込む側は「このステージのプログラムは何 MB まで動かしてよい」を決めることになる。

**確保そのものは断らない。**断ってしまうと、その場で書き換えのしようがないため。
上限を超えたことだけを覚えておき、区切りのよいところで止める。

### 超えたときの動き

| いつ | どうなる |
|---|---|
| 実行中 | 命令の切れ目で `panic` する。抱えていた値はその場で離すので、量は元に戻る |
| タスクの中 | そのタスクだけが止まる。ほかのタスクとプログラム全体は続く（[concurrency.md](concurrency.md)） |
| 移植層の確保そのものが失敗した | もう続けられないので、その場で終わる（[platform.md](platform.md)） |

```
panic: メモリを使いすぎました
  上限は 8 MB です。増え続ける配列や文字列がないか見てください
  --> main.shk:5
  呼び出しの経路:
    main.shk:5  main
```

区切りごとに見るので、**上限を少し超えてから止まる**。
1回の確保が大きいほど（文字列を倍々に伸ばすなど）、超える量も大きくなる。
上限は「ここまでしか使わない」ではなく「ここを超えたら止める」という線。

### 取りこぼしを残さない

上限が意味を持つのは、要らなくなった値がきちんと離されているときだけ。
参照カウントの取りこぼしがあると、正しいプログラムでも使用量が増え続けてしまう。
そのため処理系には、**動かし終えて片付けた後に確保量が元に戻ること**を
確かめる検査を持たせる。

## 値の大きさ

- `int` `float` `bool` は実体をそのまま持つ
- `string` `bytes` `list` `map` とクラスのインスタンスは、実体への参照＋参照カウントを持つ
  （利用者からは常にコピーに見える）
- クラスの実体には「どのクラスか」も記録する。コピーのときは一緒に複製されるので、
  親やインタフェースの型の変数に入れても中身の型は変わらない
  （[../types/class.md](../types/class.md)）
