# エラーと警告

処理系が返すエラーと警告の中身を定める。

型を厳格にした分、利用者はエラーに多く出会う。中身を固定し、どの実装でも同じものを返す。

**実行系（コア）は文字を整形しない。**下の要素を構造化データとして返すだけで、
端末に並べるのも、ゲームの画面に吹き出しで出すのも、受け取った側の仕事
（[embedding.md](embedding.md)、[../frontend.md](../frontend.md)）。
この文書の表示例は、コマンドラインのフロントエンドが整形した場合のもの。

## 3点セット

すべてのエラーは、次の3つを必ず含む。

1. **何が起きたか** — 専門用語を避けた1行
2. **どこか** — ファイル名、行、該当部分の下線
3. **どう直すか** — 書き換え例。示せないときは、何を調べればよいか

```
error[E0102]: int と float は足せません
  --> main.shk:3:13
  3 | var total = count + price;
    |             ----- int
    |                     ----- float
  直し方: float(count) + price と書くと足せます
```

## 桁の数え方

行と桁は 1 から始め、**桁は文字の数で数える**。バイト数でも、端末に並べたときの幅でもない。
`len`（下線を引く長さ）も同じく文字の数。

日本語や絵文字が同じ行にあると、この3つは食い違う。`"すし"` を含む行では、
バイトなら 1 文字が 3 つ分、端末の幅なら 2 つ分、文字なら 1 つ分になる。
受け取った側が、自分の数え方に直す。

- 端末に下線を引く — 表示幅に直す（全角は 2 つ分）
- エディタに印を付ける — その API の単位に直す（Monaco や LSP は UTF-16 の数）

## 決めごと

- 1つの誤りに対して1つのエラーだけ出す。同じ原因から派生したものはまとめる
- 内部の用語（バイトコード、スタック、単相化）をメッセージに出さない
- 「〜が不正です」で終わらせない。必ず次の行動を書く
- 番号を付ける。番号から詳しい説明を引けるようにする（表示のしかたは受け取る側が決める）
- メッセージは日本語と英語を持ち、どちらを返すかはホストが指定する。文面は処理系に埋め込む

## よく出るものと、その出し方

型を厳しくした結果よく出るものは、あらかじめ文面を決めておく。

| 番号 | 出る場面 | 直し方として示すもの |
|---|---|---|
| E0003 | 予約語を名前にした、名前を数字で始めた | 予約語でない名前、英字か `_` で始めた書き方 |
| E0101 | 型が合わない代入 | 変数の型と、入れようとした値の型 |
| E0102 | `int` と `float` を混ぜた | `float()` での変換 |
| E0103 | `if n {}` のように `bool` 以外を条件にした | `n != 0` と書く |
| E0104 | `var xs = [];` で型が決まらない | `var xs: list<int> = [];` |
| E0132 | `int` 以外にビット演算を書いた | `int()` での変換、`&&` `\|\|` との違い、`(a & b) == c` の括弧 |
| E0201 | `T?` をそのまま使った | `??` `if var` `!` の3つの選び方 |
| E0202 | `Result` を受け取らずに捨てた | `try` `if var` `_ =` の3つ |
| E0301 | `ref` を付けずに書き換えようとした | 呼ぶ側と受け取る側の両方に `ref` |
| E0302 | `ref` をタスクに渡した | 値のまま渡せばコピーされる |
| E0401 | `virtual` の無いメソッドを上書きした | 親に `virtual` を足す |
| E0402 | `override` を書き忘れた | `override` を足す |
| E0403 | 抽象クラスのインスタンスを作った | 実装していない純粋仮想の一覧 |
| E0501 | 処理系が持たないモジュールを取り込んだ | 持っているモジュールの一覧 |

```
error[E0201]: int? をそのまま int としては使えません
  --> main.shk:5:11
  5 | print(n + 1);
    |       - ここは値が無いかもしれません
  直し方: 次のどれかを選びます
    n ?? 0            値が無いときは 0 として扱う
    if var v = n { }  値がある時だけ処理する
    n!                絶対にあると分かっているとき（無ければ止まる）
```

## 警告

止めるほどではないが、たいてい誤りであるもの。

| 場面 | 内容 |
|---|---|
| GUI のイベント処理で待つ関数を呼んだ | 画面が固まる。`task` に逃がす（[../library/ui.md](../library/ui.md)） |
| 使っていない変数がある | 書き間違いの可能性 |
| 届かないコード | `return` の後ろなど |

警告は既定で表示し、`--strict` を付けるとエラーとして扱う。

## 実行時に止まったとき

`panic` で止まったときも、同じ考え方で出す。

```
panic: 配列の範囲を超えました
  xs の長さは 3 ですが、4 番目を読もうとしました
  --> fish.shk:12:7
  呼び出しの経路:
    fish.shk:12  count_fish()
    main.shk:4   main()
```

- どの値がいくつだったかを必ず出す。「範囲外です」だけにしない
- 呼び出しの経路を出す（[execution.md](execution.md)）

メモリを使いすぎて止まったときも同じ形で出す。
「メモリが足りません」ではなく、**上限がいくつだったか**と、
何が増え続けていないか調べればよいかを書く（[memory.md](memory.md)）。
