# 実行モデル

「抽象度の高いインタプリタおよび実行時コンパイル方式」を具体化する。

## 流れ

```
ソース(.shk)
   → 字句解析     文字の並びを単語に分ける
   → 構文解析     単語を構文木にする
   → 型検査       型を推論し、合わないものを弾く
   → バイトコード生成
   → 仮想マシンで実行（＋実行時コンパイル）
```

型検査までは実行前に必ず終わらせる。型の誤りでプログラムが途中まで動いてしまうことはない。

## 仮想マシン

- スタック型の仮想マシン。命令は1バイトの命令コード＋オペランド
- 命令セットはプラットフォームに依存しない。同じバイトコードはどこでも同じ結果になる
- 浮動小数点は IEEE 754 に従い、丸め方も固定する

スタック型を選ぶのは、レジスタ割り当てが要らず、移植と実装が単純になるため。

## 実行時コンパイル

同じ場所が何度も実行されたら、その部分を機械語に変換して差し替える。

- 変換の判断は関数単位。呼ばれた回数とループの回転数がしきい値を超えたら対象にする
- **実行時コンパイルは任意機能**とする。持たない移植先では、常に仮想マシンで実行する
- どちらで実行しても結果は同じでなければならない

移植のしやすさを優先し、「速くする仕組みが無くても動く」ことを保証する。

## 起動

実行系（コア）にコマンドは無い。**ホストが呼ぶ**
（[embedding.md](embedding.md)）。ソースは文字列で渡され、
コアは少しずつ実行して制御を返す。

コマンドラインから叩く `shark run` は、コアの外側に別で実装する
（[../frontend.md](../frontend.md)）。

`main` 関数が入口。`int` を返し、その値は終了の状態としてホストに渡る。
ホストがそれを終了コードにするか、ゲームの中で使うかは、ホストが決める。

## スクリプトとしても書ける

`main` を書かず、文をそのまま並べたファイルも実行できる。
最初の1行を短くするため（[../README.md](../README.md)）。

```shark
// hello.shk
print("Hello, Shark!");
```

```
shark run hello.shk
```

- 並べた文は、上から順に `main` の中身として実行される。終了コードは 0
- `main` があるファイルにトップレベルの文を書くとエラー。どちらが先か迷わせないため
- トップレベルに文を書けるのは**実行するファイルだけ**。
  取り込まれる側（[module.md](module.md)）に書くとエラー
- `import` と関数・クラスの定義は、どちらの書き方でも先頭に置ける

慣れてきて `main` を書くようになっても、動きは変わらない。

## 実行の順番

1. `import` されたモジュールを、依存の深い順に読み込む
2. 各モジュールのトップレベルの `var` / `const` を宣言順に初期化する
3. `main()` を呼ぶ。無ければ、トップレベルに並べた文を順に実行する
4. 終わったら、走っているタスクの終了を待ってから、結果をホストに返す

3 と 4 は一度に走り切るとは限らない。ホストが区切った量ずつ進む
（[embedding.md](embedding.md)）。

循環 import はエラーにする。
