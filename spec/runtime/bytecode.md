# バイトコードの保存と、単一バイナリ

型検査を通したプログラムは、**バイトコードとして保存できる**。
保存したものは、仮想マシンだけを持つ小さな実行装置で動く。
実行装置のうしろに埋めれば、**それ1つで動く1つのファイル**になる。

```
ソース(.shk) ──shark build──▶ バイトコード(.shkc) ──sharkvm──▶ 実行
                    │
                    └─▶ 実行装置＋バイトコード = 単一バイナリ ──▶ そのまま実行
```

配る相手に処理系を入れてもらわなくてよく、ソースを見せずに渡せる。
`shark` コマンド（[../frontend.md](../frontend.md)）が作り、
コアは**バイト列を作る／読む**ところだけを持つ（ファイルは触らない）。

## 実行装置には何が入らないか

コアは2つに分かれる。

| | 中身 | 保存したバイトコードを動かすのに |
|---|---|---|
| 前側 | 字句解析・構文解析・型検査・バイトコード生成 | **要らない** |
| 実行装置 | 仮想マシン・値・型の表・標準ライブラリ・移植層 | 要る |

保存したバイトコードは型検査を通っている。もう一度型を見る必要はないので、
実行装置は前側を持たない。ソースは読めず、`import` も解決しない
（読み込むときにぜんぶ入れてあるため）。

- 実行装置の入口（`Runtime`）は、Engine（[embedding.md](embedding.md)）と同じ形にする。
  ソースを渡す `load(name, source)` の代わりに、バイト列を渡す `load(bytecode)` がある
- 刻んで動かすところ（`step`）と、入出力の渡し方は Engine と同じ

## 何を入れるか

仮想マシンが動くのに要るものだけを入れる。

| 入れる | なぜ |
|---|---|
| 命令の並び、定数、行番号 | 実行と、panic の位置に使う |
| 関数（名前・引数・戻り・所在） | 呼び出しと、呼び出しの経路の表示に使う |
| クラス（メンバ・仮想関数の表） | 実体を作り、`virtual` を呼ぶのに使う |
| グローバルと、その型 | 最初の値を作るのに使う |
| 走らせる順（モジュールの初期化と入口） | 起動に使う |

| 入れない | なぜ |
|---|---|
| 構文木 | 実行に要らない |
| ソースそのもの | 実行に要らない。診断の行の中身は出せなくなる |
| 診断の位置（列・下線） | 型検査は終わっている |

処理系が持つ関数（`print` や `math.abs`）は**番号**で指す。番号は登録の順で決まるので、
ファイルには**表の指紋**（名前と引数の数から作る値）を入れ、
読むときに突き合わせる。合わなければ、そこで止めて作り直しを促す。
処理系が持つクラスのメソッド（`Error.message` など）は、
関数の場所を書けないので**名前**で入れ、読むときにつなぎ直す。

## ファイルの形

```
"SHKC"            4 バイトの目印
版                4 バイト
もとのファイル名    診断（panic）に出す名前
診断の言語 / メモリの上限 / 入れた標準ライブラリの組み合わせ
関数の表の指紋      8 バイト
型・クラス・関数・グローバル・走らせる順
```

- 数は可変長で入れる（下位 7 ビットずつ、続きがあれば最上位ビットを立てる）。
  符号つきの数は、正負を交互に並べる形に直してから入れる
- 位置を指すもの（型・クラス・関数）は番号で、「無い」は `-1`
- 型は**指す先が先に来る順**に並べる。読むときは前から順に組み立てられる
- 命令の並びはそのまま入れる。命令の意味は [execution.md](execution.md) が決める

版と指紋が合わないファイルは読まない。
入れる標準ライブラリは、ファイルに書いてある組み合わせに合わせて用意する
（関数の番号を揃えるため）。
**保存したバイトコードは、同じ版の処理系で作り直せる前提**で扱う
（配布形式としての互換は約束しない）。

読むときは、番号が範囲に収まっているかを見て、壊れていれば実行前に止める。
ただし、**命令の並び自体が正しいかは検査しない**。
実行装置は、渡されたバイトコードを信頼して動かす。
検査は「取り違えや壊れ」を見つけるためのもので、
悪意のある書き換えを防ぐものではない。

## 単一バイナリ

実行装置のうしろにバイトコードを足し、最後に目印を置く。

```
[ 実行装置（そのまま） ][ バイトコード ][ "SHARKPK1" ][ 長さ 8 バイト ]
```

- 動くときは、自分自身のファイルの末尾を見て、あれば読んで動かす
- 目印を**うしろ**に置くのは、前に足すと実行ファイルの形が壊れるため
- 埋まっているときは、命令行の引数を**ぜんぶプログラムに渡す**。
  メモリの上限や診断の言語は、作るときに決めてファイルに入れておく
- 実行ファイルの形（ELF / Mach-O / PE）には手を入れない。
  足したぶんは、その形の外側にある
- そのため、署名を確かめる仕組みを持つ機種では、
  「うしろに余りがある」と見なされることがある（macOS の `codesign -v` はそう言う）。
  動かすぶんには足りるが、**配るときの署名は別の手当てが要る**

配るファイルの大きさは「実行装置＋バイトコード」。
前側（字句解析から先）が入らないぶん、処理系そのものより小さくなる。

## ゲームに組み込むとき

同じ仕組みは、コマンドの外でも使える。
**作者が用意したステージ**を先にバイトコードにしておけば、
ゲーム本体は前側を持たずに済む（[embedding.md](embedding.md)）。

- ホスト関数は、作るときと動かすときで**同じものを同じ順に**登録する。
  番号がずれたものは、指紋が合わないので読むときに止まる
- プレイヤーがその場で書くコードは、これまでどおりソースから読む。
  どちらも同じ仮想マシンが動かす

動く例: [../../examples/embed/play_stage.cpp](../../examples/embed/play_stage.cpp)
