# コアの雛形

実装として作るのは**コアだけ**。
それを、**そのまま使えるところまで作り込んだ雛形**として配る。
使う側は、自分のゲームに合わせて必要なところだけ手を入れる。

## 考え方

**できるだけ完成した状態で配る。**使う側が書き換える場所は、できるだけ少なくする。

雛形と呼ぶのは「未完成だから埋めてください」という意味ではなく、
**自分のゲームに合わせて手を入れてよい**という意味。
そのうえで、手を入れる場所は次の2か所に絞る。

| 触る場所 | 何をするか |
|---|---|
| `platform/` | 自分の機種のものに差し替える |
| `host` | ゲーム側の操作を関数として足す |

ここ以外は、そのまま使えることを目指す。

## 何を入れるか

| 区分 | 中身 |
|---|---|
| 必ず入れる | 字句解析、構文解析、型検査、バイトコード生成、仮想マシン、値と参照カウント、メモリの上限、診断、必須ライブラリ（`time` `math` `task`） |
| 入れておく | 実行時コンパイル、`file` `path` `text` `fmt` `json` `net` `http` `os` `ui` `test` |
| 入れない | コマンドライン、ファイルの読み込み、端末への出力（[frontend.md](frontend.md)） |

標準ライブラリは**全部入れた状態**で配る。
要らないモジュールは、ファイルを消すのではなく**ビルドに含めない**
（[library/overview.md](library/overview.md)）。
消してしまうと、後から雛形の直しを取り込むときに衝突する。

## 実装に使う言語

**C++** を使う。ゲーム機に載せることを考えた上での選択。

| 決めごと | 理由 |
|---|---|
| 例外を使わない | ゲーム機では無効化されることが多い。言語自身も例外を持たない（[runtime/error.md](runtime/error.md)） |
| RTTI を使わない | 同上。クラスの型判別は自前で持つ（[runtime/memory.md](runtime/memory.md)） |
| 標準ライブラリへの依存は薄く | どの機種にもある範囲に限る（[runtime/platform.md](runtime/platform.md)） |
| 外部ライブラリを使わない | 思想のとおり |

規格をどれに合わせるかは、載せる機種のコンパイラに合わせて実装時に決める。

## ファイルの分け方

書き換える場所がひと目で分かるようにする。

```
core/
  lexer      字句解析
  parser     構文解析
  types      型検査
  codegen    バイトコード生成
  vm         仮想マシン
  value      値、コピー、参照カウント
  diag       診断（メッセージの表）
  host       ホスト関数の表        ← 書き足す場所
  platform/  移植層                ← 差し替える場所
    desktop
    console
  lib/       標準ライブラリ        ← 全部入れておく
    time  math  task
    file  text  json  ui  ...
```

- `platform/` は1つ選んで使う。新しい機種に載せるときは、ここに1つ足す
- `host` に書き足した関数が、そのままプレイヤーの書くコードから呼べる
  （[runtime/embedding.md](runtime/embedding.md)）

## 配り方

**git で配る。**使う側はそれを複製して、自分のゲームの中で使う。

- 雛形が直ったら、上流から取り込む（merge）
- 触る場所を `platform/` と `host` に絞ってあるので、取り込みで衝突しにくい
- 逆に、コアの中身を書き換えるほど、取り込みが大変になる

「書き換えられる」ことと「書き換えなくて済む」ことは両立させる。
**書き換えてよいが、しなくて済むように完成させておく。**

## 書き換えの指針

| してよいこと | ただし |
|---|---|
| 移植層を差し替える | そのために用意してある場所 |
| ホスト関数を足す | 同上 |
| 要らないモジュールをビルドから外す | ファイルは消さない |
| 診断の文面を直す | 番号と意味は変えない |
| 1回の `step()` で進める命令数を変える | 結果は変わらない（[runtime/embedding.md](runtime/embedding.md)） |

| してはいけないこと | 理由 |
|---|---|
| 構文を変える | 別の言語になる。学習用の教材が通じなくなる |
| 型の規則を変える | 同上。暗黙変換を足す、`null` を足す、なども含む |
| 残した関数の意味を変える | 同じ名前で違う動きをするものが増える |

## Shark と名乗る条件

1. [syntax.md](syntax.md)、[types/](types/)、[runtime/](runtime/) の規則を満たすこと
2. 残した標準ライブラリが [library/](library/) のとおりに動くこと
3. 削ったものを、使う人に分かる形で書いておくこと

3 を守れば、削ることは仕様違反にならない。
むしろ、ゲーム機に載せるには削ることが前提になる。
