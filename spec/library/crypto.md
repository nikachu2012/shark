# std.crypto

ハッシュと、当てられては困る乱数。

```shark
import std.crypto;
```

`std.math` の乱数とは役割が違う。さいころのように「当てられてもよい」乱数は
`math.random`、合言葉や鍵のように「当てられては困る」乱数はこちら。

## ハッシュ

元に戻せない短い指紋を作る。`bytes` を返し、`string` でも `bytes` でも渡せる
（`string` は UTF-8 の並びをそのまま数える）。

| 関数 | 長さ | 説明 |
|---|---|---|
| `crypto.sha256(data) -> bytes` | 32 バイト | 迷ったらこれ |
| `crypto.sha512(data) -> bytes` | 64 バイト | もっと長いものが要るとき |
| `crypto.sha1(data) -> bytes` | 20 バイト | 古い決まりに合わせるときだけ |
| `crypto.md5(data) -> bytes` | 16 バイト | 取り違えを見つけるときだけ |

```shark
print(crypto.sha256("abc").to_hex());
// ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

`sha1` と `md5` は**もう安全ではない**。中身が違うのに同じ指紋になるものを人が作れる。
新しく作るものには使わない。消さずに置いてあるのは、古いデータと突き合わせるため。

## 鍵つきのハッシュ

| 関数 | 長さ |
|---|---|
| `crypto.hmac_sha256(key, data) -> bytes` | 32 バイト |
| `crypto.hmac_sha512(key, data) -> bytes` | 64 バイト |

鍵を知っている人だけが同じ値を作れる（HMAC、RFC 2104）。
「確かに自分が作った」という印になる。

## 見せる

ハッシュは `bytes` で返る。目に見える形にするのは**型の側**の仕事で、
`std.crypto` は持たない（[builtin.md](builtin.md)）。

| メソッド | 説明 |
|---|---|
| `b.to_hex() -> string` | 16 進の文字列にする（小文字） |
| `s.from_hex() -> bytes?` | 16 進から戻す。読めなければ `none` |

16 進はハッシュに限らずバイト列ぜんぶに要るもので、
`std.crypto` を入れていない処理系でも使えるようにしてある。

## 見比べる

| 関数 | 説明 |
|---|---|
| `crypto.equal(a, b) -> bool` | 時間の差が出ない比べ方 |

`equal` の結果は `==` と同じ。違うのは**掛かる時間が中身で変わらない**こと。
途中まで合っているほど返事が遅い、という差から中身を当てられるのを防ぐ。
合言葉や印を見比べるときは、こちらを使う。

## 乱数

| 関数 | 説明 |
|---|---|
| `crypto.random_bytes(n: int) -> bytes` | n バイト（0 〜 1048576） |
| `crypto.random_int(lo: int, hi: int) -> int` | `lo` 以上 `hi` 以下。偏らない |
| `crypto.uuid4() -> string` | 重ならない名前。UUID の版4（乱数から作る形）。36 文字 |
| `crypto.source() -> string` | いまの出どころ |

```shark
var key = crypto.random_bytes(32);
print(key.to_hex().len());     // 64
```

### 出どころを隠さない

**真の乱数を先に試し、取れないときだけ暗号学的に安全な乱数に落ちる。**
どちらから取れたかは `crypto.source()` で分かる。

| 戻り値 | 意味 |
|---|---|
| `"true"` | 機器の雑音から作る真の乱数。先が読めない |
| `"secure"` | 暗号学的に安全な乱数。種から作るが、種も次の値も当てられない |
| `"none"` | もとが無い。乱数の関数は実行時エラーになる |

```shark
if crypto.source() == "true" { print("機器の乱数を使っている"); }
```

`source()` は覚えておいた答えではなく、**そのつど本当に取ってみて**返す。
雑音が尽きれば同じ機種でも出どころは変わるため。

落ちる先を `"secure"` までとしたのは、`std.math` のような種から作る乱数で
埋めてしまうと、当てられる乱数を安全なものだと思って使ってしまうため。
もとが無い機種では、黙って弱い乱数を返さず**実行時エラーにする**。
使う前に `source()` を見れば、持っているかどうかが分かる。

## 移植層とのつながり

ハッシュは処理系に埋め込むので、どこでも同じように動く。
乱数のもとだけは機種に頼る（[../runtime/platform.md](../runtime/platform.md) の任意項目）。

| 移植層が渡すもの | `source()` |
|---|---|
| 真の乱数（x86 の RDSEED、機器の乱数器） | `"true"` |
| OS の暗号用乱数（`getentropy` `/dev/urandom` `rand_s` `crypto.getRandomValues`） | `"secure"` |
| どちらも無い | `"none"` |

任意モジュール。ハッシュだけなら移植層の必須項目だけで動くので、
乱数のもとを持たない機種でも `import` はできる。

なお、乱数は「同じ入力なら、どの環境でも同じ結果を返す」
（[overview.md](overview.md) の決めごと）に**当てはまらない**。
毎回違う値を返すことが役目だからで、`math.seed` のように種で固定する道も用意しない。
固定できる乱数が要るなら `std.math` を使う。

## 決めていないこと

- 大きなファイルを少しずつハッシュにかける形（いまは一度にまとめて渡す）
- 公開鍵の署名（Ed25519 など）。埋め込む大きさと、学習用としての要否を見てから決める
