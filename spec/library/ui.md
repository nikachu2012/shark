# std.ui

画面に描くところを担当する。

```shark
import std.ui;
```

## 考え方

層は2つ。**下の層**が土台で、**上の層**はその上に載っている。

| 層 | 渡すもの | 使うもの |
|---|---|---|
| 下 | **面**（画素の並び1枚）と**出来事**（キー・マウス） | `ui.clear` `ui.line` `ui.text` `ui.key` … |
| 上 | 「いまどうあるべきか」を組んだ**部品1つ** | `ui.label` `ui.button` `ui.col` … と `ui.show` |

下の層に窓もボタンも無いのは、部品を決めると**その見た目と作法まで決めてしまう**ため。
学習用ゲームの中では、ゲームに合った見え方が要る。

そのぶん、この層は移植先で詰まらない。移植層に求めるのは
「面を画面に出す」と「出来事を渡す」の2つだけで、描くのは全部こちらで行う
（[../runtime/platform.md](../runtime/platform.md)）。

上の層は、**下の層だけで書かれている**。特別な仕組みは何も要らない。
だから上の層で足りないところは、下の層で自分で描いて混ぜられる。

## 動かし方

くり返しの形はいつも同じ。

```shark
ui.open("さかな", 160, 120);
while ui.poll() {                       // 1. 押された・動いた を取り込む
  if ui.pressed("esc") { ui.quit(); }
  ui.clear(ui.rgb(0, 20, 40));          // 2. 描く
  ui.fill_circle(80, 60, 20, ui.rgb(255, 140, 60));
  ui.present();                         // 3. 画面に出す
  ui.frame();                           // 4. 次のこまの刻みまで待つ
}
ui.close();
```

- `ui.poll()` は**待たない**。押されていなければそのまま返る
- `ui.key()` などが答えるのは「最後に `poll` したときの様子」で、その間は変わらない。
  1回のくり返しの中で、同じことを何度尋ねても答えは同じになる
- 描いただけでは画面は変わらない。`ui.present()` でまとめて出す

`ui.frame()` はタスクを譲るだけで、ゲームに組み込んだときは `step()` がホストに返る
（[../runtime/embedding.md](../runtime/embedding.md)）。**画面つきでも固まらない。**

### こまの速さ

**待つのは `sleep()` ではなく `ui.frame()`。**この2つは似ていて、結果が違う。

| 書き方 | 1こまにかかる時間 |
|---|---|
| `sleep(0.016)` | 描くのにかかった時間 **＋** 16ms |
| `ui.frame()` | 16.7ms（描くのにかかった時間を**含む**） |

`sleep` は「眠る長さ」しか決められないので、描くのにかかった分だけ足が出る。
`ui.frame()` は**次のこまの刻限**を決めて、そこまで待つ。追いつけていないときは
刻限を取り直すので、遅れがたまることもない。

足が出ると困るのは、**プログラムを進めるきっかけをホストが握っている機種**。
ブラウザは 1 秒に 60 回しかプログラムを進めない（`requestAnimationFrame`）ので、
刻限のすぐ後ろに起きると**その回に間に合わず、次のきっかけまで丸ごと待つ**。
`sleep(0.016)` と書くだけで、それだけで速さがちょうど半分（30）になる。

そういう機種は移植層が `PlatformScreen::host_paced` を `true` にして名乗る。
`ui.frame()` はそのとき**刻限の半こま手前で起きる**。半こまなのは、描くのに
その半分より長くかかっているなら、どのみち間に合っていないから。
きっかけを自分で作れる機種（`shark` コマンド）では、刻限ちょうどまで待つ。

`ui.frame(fps)` で速さを変えられる（1〜1000）。`ui.run()` も中でこれを使う。

## 面

`ui.open(横, 縦)` で画素の並びを1枚作る。大きさは画素の数で、画面の細かさには合わせない。
ゲーム機のように決まった大きさに描き、出すときに引き伸ばす。

**画面が無くても開ける。**画面を持たない機種や、出力をファイルに流しているときは、
描く先が**見えない面**になるだけで、描き方は何も変わらない。

| | 画面あり | 画面なし |
|---|---|---|
| `ui.open` | 面を作り、画面も開く | 面を作る |
| 描く | 同じ | 同じ |
| `ui.present` | 画面に出す | 何もしない |
| `ui.poll` | 出来事を取り込む | 何も起きないまま `true` |
| `ui.get` / `ui.to_png` | 取り出せる | 取り出せる |

見分けるのは `ui.visible()`。分けて書く必要があるのは、
出せないときに別のことをしたい場合（結果を PNG で保存するなど）だけ。

### 窓の大きさを変えたとき

窓の縁を引いて大きさを変えると、次の `ui.poll()` で**面が同じ大きさに作り直される**。

- `ui.width()` / `ui.height()` が新しい数を返す。毎回この2つを見て描いていれば、それだけで付いてくる
- 宣言的な層（`ui.run`）は毎回組み直して描くので、何もしなくても新しい大きさに広がる
- 前に描いた中身は左上に残り、広がったところは下地の色になる。ふつうは次の描き直しで消える
- 縁を引いている**最中**も、宣言的な層（`ui.show` / `ui.run`）を使っていれば、
  **最後に見せた部品を新しい大きさで置き直す**ので、折り返しも取り分（fr）も付いてくる
  （macOS は引いている間 OS がプログラムを止めるので、view() の呼び直しは手を離してから。
  それまでは覚えておいた部品を置き直している）。
  自分で描くだけのプログラム（macOS）では、最後の絵が等倍のまま左上に置かれ、
  余白は端の色で埋まる。X11 では引いている間もプログラム自身が描き直し続ける
- 切り抜き（`ui.clip`）は面いっぱいに戻る
- 大きさを渡してこない出し先では、面は開いたときのままで変わらない
- 変えられては困るときは、`ui.open(title, w, h, false)`（`ui.run` なら末尾に `false`）で
  **大きさの変わらない窓**にできる。省くと変えられる

### 細かい画面（HiDPI）

面の1画素は、画面の1画素にそのまま乗る。だから**細かい画面では、面も細かく取る**。

```shark
var k = ui.scale();                  // ふつうは 1、細かい画面なら 2
ui.open("さめ", 420 * k, 300 * k);   // 見た目の大きさは変わらない
_ = ui.font(12 * k);                 // 12pt くらい
```

- `ui.scale()` は**開く前に呼べる**。面の大きさを決めるのに要るため
- 窓の大きさは「面の画素 ÷ 細かさ」で決まる。上の例なら、どちらの画面でも
  見た目は 420×300 で、細かい画面ではその中の点が2倍細かくなる
- **面の大きさは、そのまま窓の大きさになる。**320×240 を頼めば 320×240 の窓が開く
- 例外は**切手のように小さい面**（広げても 320×240 に収まるもの）だけ。
  そこだけ整数倍に引き伸ばす。ゲーム機のような粗い絵を大きく出したいときのため。
  引き伸ばしは画素をそのまま並べるだけなので、字も丸も粗くなる

寸法を書くときに `* k` を掛けるかどうかは、書く人が決める。
掛けなければ「画素できっちり」、掛ければ「どの画面でも同じ見た目」になる。

この決め方のおかげで、**画面の要る書きものをテストできる**。
描いてから `ui.get()` で色を確かめれば、画面のない場所でも動きを確かめられる。

## 色

色は `int` 1つ。上から赤・緑・青の 8 ビットずつで、`0xRRGGBB` と同じ並び。

```shark
var red = ui.rgb(255, 0, 0);      // 16711680
print(ui.red(red));               // 255
```

### 濃さ（透明）

`ui.rgba(r, g, b, a)` で**濃さ**を足せる。`a` は 255 で不透明、0 でまるごと透明。
`ui.rgb(r, g, b)` は `ui.rgba(r, g, b, 255)` と同じ色で、**返す数も今までと変わらない**。

```shark
ui.fill_rect(0, 0, 8, 8, ui.rgba(255, 255, 255, 128));   // 下が透けて見える
print(ui.alpha(ui.rgb(1, 2, 3)));                        // 255
```

速さのために、**混ぜるかどうかは色を見て決める**。不透明な色は今までどおり
そのまま書き込み、まるごと透明な色は何もしない。混ぜるのは半透明のときだけ。

**「そのまま置く」ものと「混ぜる」もの**が分かれている。

| | |
|---|---|
| そのまま置く | `ui.set` `ui.clear` `ui.blit` |
| 半透明なら混ぜる | `ui.line` `ui.rect` `ui.fill_rect` `ui.circle` `ui.fill_circle` `ui.text` `ui.tri` `ui.draw` |

`ui.set` が混ぜないのは、混ぜると**透明にできなくなる**ため
（透明を重ねても、下地が残るだけで何も起きない）。
`絵.set(x, y, ui.rgba(0, 0, 0, 0))` が絵を直す道具の「消しゴム」になる。
読んで書き戻せば同じ色になる（`ui.set` と `ui.get` は往復する）。

**画面の面は不透明で始まる。**`ui.open()` は不透明な黒で埋め、その上に
半透明を**重ねても**不透明のまま残る。透明が入るのは、混ぜずに置く
`ui.set` / `ui.clear` / `ui.blit` に透明な色を渡したときだけ。

画面に出すときは、どの機種も濃さを見ない（いちばん上のバイトを捨てる）ので、
画面の見た目は変わらない。濃さが意味を持つのは絵（`Canvas`）のほうで、
`ui.to_png()` は透明が入っていればそのまま書き出す。

## 描くもの

| 関数 | |
|---|---|
| `ui.clear(color)` | ぜんぶ塗る |
| `ui.set(x, y, color)` / `ui.get(x, y)` | 点を打つ / 読む |
| `ui.hline` `ui.vline` `ui.line` | 線 |
| `ui.rect` / `ui.fill_rect` | 四角（枠 / 中まで） |
| `ui.circle` / `ui.fill_circle` | 円（枠 / 中まで） |
| `ui.blit(x, y, w, pixels)` | 画素の並びをそのまま置く |
| `ui.draw(image, x, y)` | 絵を貼る（下を透かす。大きさを渡せば伸び縮み） |
| `ui.tri(...)` | 三角形（奥行きつき） |
| `ui.clip(x, y, w, h)` / `ui.clip_off()` | ここから外には描かない |

面の外に描いても何も起きない。止まらない。座標を毎回確かめずに書けるようにするため。

多角形は持たない。`ui.hline` や `ui.tri` を並べれば書けるので、
**組み合わせで書けるものは足さない**。
三角形だけを持つのは、そこに**奥行きのくらべっこ**（z バッファ）が要るため。
これは組み合わせでは書けない（下の「三角形と奥行き」）。

## 絵（Canvas）

画面のほかにも描ける面を持てる。`ui.canvas(横, 縦)` で作り、`ui.load_png()` で読む。

```shark
var e = ui.canvas(16, 16);             // まるごと透明で始まる
e.fill_rect(2, 2, 12, 12, ui.rgb(240, 80, 60));
ui.draw(e, 100, 50);                   // 画面に貼る
```

使い道は3つ。

- **絵を出す。**PNG を読んで貼る
- **先に描いておいて何度も貼る。**スプライトや地形。毎こま描き直すより速い
- **3D の描き先。**`絵.tri()` と `ui.depth()`

### ふつうの値である

`Canvas` は**ハンドルではなく、ふつうの値**。代入すればコピーになる
（`File` や `Task` とは違う。[../runtime/memory.md](../runtime/memory.md)）。

```shark
var 控え = 絵;        // ここでは写さない（参照数が増えるだけ）
絵.clear(0);          // 書き換えるここで、初めて写る
```

中身は参照数を数えていて、書き換えるまで写さない（copy on write）。
だから「直す前に控えを取る」が安く書ける。**絵を直す道具の「取り消し」が、
これだけで済む**ようにしてある。

### 描くのは、画面と同じ名前

絵に描くメソッドは、画面に描く `ui.*` と**同じ名前・同じ引数**。描き先だけが違う。

```shark
ui.line(0, 0, 10, 10, red);    // 画面に
絵.line(0, 0, 10, 10, red);    // 絵に
```

持っているのは `width` `height` `get` `set` `clear` `hline` `vline` `line`
`rect` `fill_rect` `circle` `fill_circle` `blit` `text` `draw` `tri`
`clip` `clip_off` `to_png`。切り抜き（`clip`）は絵ごとに覚えている。

描き先を大域で切り替える形（`ui.target(絵)` のようなもの）は**採らなかった**。
切り替えたまま絵が消えると、描き先が行き場を失うため。
メソッドなら、その1回の呼び出しの間しか描き先が変わらない。

### PNG

`ui.load_png(data)` で読み、`絵.to_png()` で書く。**読む → 直す → 書き戻す**で
透明は失われない。

- 読めるのは**編み込み無し**（interlace 0）のもの。白黒・白黒＋透明・色つき・
  色つき＋透明・パレットのどれでもよく、深さは 1/2/4/8/16 ビット。
  16 ビットは 8 ビットに落とす。読めなければ `none`
- 書くときは、透けているところが1つでもあれば透明つき（色の型 6）、
  なければ赤緑青だけ（色の型 2）。**透明を使わない絵は、今までと同じ大きさのまま**
- 縮めずに入れるので、同じ絵の PNG より少し大きい（展開は自前で書いてあるが、
  圧縮は持たない）

## 三角形と奥行き

3D で**組み合わせでは書けないのは奥行きのくらべっこだけ**。そこだけをここに置き、
回す・遠近をつけるといった見え方の計算は Shark の側で書く。

```shark
ui.depth(true);
while ui.poll() {
  ui.clear(0);
  ui.clear_depth();                       // ひとこまごとに戻す
  // x, y, z は Shark の側で計算した「面の上の座標」
  ui.tri(x0, y0, z0, x1, y1, z1, x2, y2, z2, color);
  ui.present();
}
```

- `ui.tri(x0,y0,z0, x1,y1,z1, x2,y2,z2, color)` — 頂点は面の座標と奥行き。
  **z は小さいほど手前**
- `ui.depth(on)` — 奥行きの面（z バッファ）を使うかどうか
- `ui.clear_depth()` — ぜんぶ「いちばん遠い」に戻す
- 表と裏の選り分けはしない（どちら回りでも塗る）。要るなら、3つの頂点の向きから
  書く人が決める
- つぶれた三角形（面積 0）は何も描かない
- 奥行きの面は**1枚だけ**を使い回す。描き先の大きさに合わせて取り直す。
  1度に描くのは1つの面なので、これで足りる

`ui.depth(false)` のときは、あとに描いたほうが上になる（ただの塗りつぶし）。

## マウスの形

押せるところに合わせたら手にする、といったことは `ui.cursor()` で頼む。

```shark
while ui.poll() {
  if ui.mouse_x() < 40 { ui.cursor("hand"); }   // ここは押せる、という見せ方
  ui.clear(0);
  ui.present();                                 // ここで機種に伝わる
  ui.frame();
}
```

- 頼めるのは `arrow` `hand` `text` `cross` `wait` `resize_x` `resize_y` `move` `none`
- **その回かぎり**。次の `ui.poll()` で `arrow` に戻る。
  「いまその場所にふさわしい形」を毎回言う、という決め方にしてある
  （状態を持たないので、部品を消したのに形が残る、ということが起きない）
- 機種に伝わるのは `ui.present()` のとき。変わったときだけ伝える
- **宣言的な層は自分で変える。**ボタン・つまみ・メニューの上では手に、
  入力欄の上では文字の形になる。書く人は何もしなくてよい
- 持っていない形は近いものになる。形を持たない出し先では何も起きない。
  `none` は「自分でマウスを描く」ときに使う

## 文字

字の出どころは3つ。**既定は内蔵**で、`ui.font()` を呼んだときだけ切り替わる。

| | 内蔵の 5×7 | 機種のフォント（FreeType） | 機種が描いてくれる字 |
|---|---|---|---|
| 出せる字 | ASCII だけ。ほかは □ | フォントが持っているぶん（日本語も）。無い字は控えのフォントから（下） | 同じ（日本語も） |
| 大きさ | 1文字ぶんの枠が 6×8。倍率は整数倍 | フォントの寸法。`ui.font()` で画素の大きさを指定 | 同じ |
| 縁 | 塗るか塗らないかだけ | なめらか（下地と混ぜて描く） | なめらか |
| どこでも同じか | **同じ** | 機種のフォント次第で変わる | 同じく変わる |
| 要るもの | なし | FreeType（任意。無ければ内蔵のまま） | 移植層の `PlatformFont`（ブラウザはこれ） |

上の2つ目と3つ目は、コアから見ると同じもの（濃さの並びと置き場所）を返す口で、
`ui.font()` は FreeType → 移植層 → だめなら false、の順に試す。
どれを使っているかは `ui.font_name()` で分かる。

```shark
ui.text(4, 4, "score 120", ui.rgb(255, 255, 255));
ui.text(4, 16, "BIG", ui.rgb(255, 255, 255), 3);   // 3倍

if ui.font(15) {                                   // 機種のフォントを読む
  ui.text(4, 40, "こんにちは", ui.rgb(255, 255, 255));
}
```

- `ui.text_width()` と `ui.text_height()` は、**そのときの字の出どころ**で答える
- 部品（`ui.button` など）の大きさも、字の大きさから決まる。
  フォントを変えても、細かい画面で字を大きくしても、釣り合いは崩れない
- 大きさは画素で渡す。**12pt くらいなら `ui.font(12 * ui.scale())`**
- `ui.text_height()` は**字の上端から下端まで**（ascender − descender）。
  フォントの持つ「次の行までの送り」は使わない。あれは行間のあきを含んでいて、
  そのまま1行の高さにすると**字の下にあきが残る**（ヒラギノなら 24 画素の字で 11 画素）。
  改行のときだけ、その 1.25 倍ずつ下げる

### 持っていない字は、控えのフォントから

1本のフォントに世界中の字は入っていない。いま使っているフォントに無い字が来たら、
**機種のフォントから順に探す**（フォールバック）。

| | |
|---|---|
| 探す順 | `SHARK_FONT_FALLBACK`（`;` 区切り）→ 機種のフォント（記号 → 絵文字 → ハングル → 日本語） |
| いつ読むか | **要るときに1本ずつ**。足りていれば1本も読まない |
| 見つからなければ | □（`.notdef`）。無いことが見て分かるように、そのまま出す |
| 行の高さ・基準線 | **本命のフォント**で決まる。控えが混じっても行が揺れない |
| 抱える数 | 4本まで。フォントは1本 10 MB を超えることもあるため |

- 読んだ控えは**抱えたままにする**。「この字が無かったから捨てる」にすると、
  あとで来た別の字をそのフォントが持っていても、もう見に行けない
- **色は付かない。**色つきの絵文字は形だけを使い、`ui.text()` に渡した色で出る
- `ui.font_name()` が返すのは**本命**の場所。控えは出てこない

### なぜ既定を内蔵にするか

「同じ入力なら、どの環境でも同じ結果を返す」（[overview.md](overview.md)）を、
何もしないうちは保つため。機種のフォントを読むと `ui.text_width()` の答えが変わり、
同じプログラムの見た目も機械ごとに変わる。**それを選ぶのは書く人**にした。

### なぜフォントだけ外に頼るか

日本語の字形を自前で抱えると、常用の漢字だけでも点の表が数百 KB になる。
処理系の大きさ（いま 1 MB ほど）に対して大きすぎるので、**ここだけ**
外のライブラリ（FreeType）に頼ることにした（[../runtime/platform.md](../runtime/platform.md)）。

- **任意**。入っていなければ、そのまま内蔵の字形だけで動く
- 読んだフォントと字形の覚え書きは処理系の持ちもので、
  プログラムのメモリ（`--memory`）には数えない
- 移植層に足すものは無い。フォントを読むのは既存のファイル機能（`PlatformFile`）

入れ方は README の「日本語の字を出す」。

## 入力

| 関数 | |
|---|---|
| `ui.poll()` | 取り込む。閉じてくれと言われていたら `false` |
| `ui.key(name)` | いま押されているか |
| `ui.pressed(name)` / `ui.released(name)` | この刻みで押された / 離された |
| `ui.typed()` | この刻みで打たれた文字 |
| `ui.mouse_x()` `ui.mouse_y()` `ui.mouse(b)` `ui.clicked(b)` | マウス |
| `ui.wheel()` / `ui.wheel_x()` | 車輪（ホイール）が送られたぶん。行の数で、下と右が正 |
| `ui.quit()` | 閉じてくれと言われたことにする |

キーの名前は、印字できる文字ならその文字そのもの（`"a"` `"1"` `"-"`）。
大文字と小文字は区別しない。そのほかは
`"left"` `"right"` `"up"` `"down"` `"space"` `"enter"` `"esc"` `"tab"` `"back"`
`"delete"` `"home"` `"end"` `"pageup"` `"pagedown"` `"shift"` `"ctrl"` `"alt"` `"meta"` `"f1"`〜`"f12"`。
`"meta"` は macOS の Command、Windows の Windows キー、Linux の Super。

打たれた文字（`ui.typed()`）とキー（`ui.key()`）を分けているのは、
文字を入れる場面と、操作に使う場面が別のものだから。
入力欄には `ui.typed()`、移動には `ui.key()` を使う。

### 押しっぱなしが分からない機種

「離した」を教えてくれない機種がある。
そこでは**押された刻みの間だけ** `ui.key()` が `true` になる。
移植層が「離した」を出せるかどうかは `PlatformScreen.has_key_up` で伝える。

押しっぱなしで動かし続けたいものは、機種の作りに任せずに、
自分で向きを覚えておくと、どこでも同じに動く。

```shark
if ui.pressed("right") { dir = 1; }
if ui.pressed("left")  { dir = -1; }
if ui.pressed("space") { dir = 0; }
x += dir;
```

### 日本語などの入力（IME）

**変換は OS に任せて、結果だけ受け取る。**変換中の下線や候補一覧まで自前で描くと、
機種ごとの作り込みが際限なく増えるため。

| 出し先 | どうなるか |
|---|---|
| 窓（macOS） | OS の変換が効く。変換中の文字は `ui.marked()` で取れ、確定したものが入る |
| 窓（Windows） | 同上（IMM32）。候補の一覧は OS のものが入力欄のそばに出る |
| ブラウザ | 見えない `textarea` に任せる。ブラウザの変換がそのまま効く |
| 窓（X11） | まだ変換を渡せない（XIM を持っていない）。打った文字がそのまま入る |
| 画面なし | 打った文字がそのまま入る |

見分けるのは `ui.has_ime()`。どの場合でも、書く側のコードは同じでよい。

```shark
var name = "";                                   // 一番外側の var
while ui.poll() {
  _ = ui.show([ui.field(ref name)]);             // 中で下の口を使っている
  ui.present();
}
```

自分で入力欄を描くときは、低い層の口を使う。

```shark
name = ui.input(x, y, h, name);      // 受け付けているあいだ、毎回呼ぶ
var mid = ui.marked();               // 変換中の文字（下線をつけて出す）
ui.input_off();                      // やめる
```

- **変換中のキーは、アプリには届かない。**`enter` は確定、`esc` は取り消し、
  空白と矢印は候補選びに使われるため。届いてしまうと、確定した拍子に
  入力欄から出たり、`esc` でプログラムが終わったりする
- 中身を持つのは**呼んだ側**。`ui.input()` は確定した中身を返すので、
  それを持ち直す（部品が状態を持たないのと同じ考え）
- 位置を渡すのは、変換の候補をそのあたりに出してもらうため
- 呼ぶのをやめると、次の `ui.poll()` で受け付けも止まる
- **変換中は、カーソルを動かさない。**受け皿が変換中の字も1つの文字列として持つ
  機種では、「選んでいるところ」に変換中の字が数に入っているのに、返ってくる
  確定文字列には入っていない。**物差しが違う**ので、そのまま合わせると変換中の字が
  増えるたびに1文字ずつずれる。変換を始めたところに置いたままにして、確定してから
  数え直す（[../../docs/implementation.md](../../docs/implementation.md)、
  見張りは `tests/imecheck.cpp`）

移植層に求めるのは2つだけ（[../runtime/platform.md](../runtime/platform.md)）。

| | |
|---|---|
| `text_input(on, initial, x, y, h, multiline)` | 受け付けを始める・やめる。位置と、複数行かを渡す |
| `text_state(&confirmed, &marked)` | いまの中身と、変換中の文字列 |

どちらも無くてよい。無ければ、打たれた文字（`SEV_Text`）をそのまま入れる。

## 取り出す

`ui.to_png()` で、いまの面を PNG にして返す。

```shark
var png = ui.to_png();
_ = file.write_bytes("shot.png", png);
```

外の圧縮の道具に頼らないよう、zlib の「そのまま入れる」形だけを使う。
縮まないぶん大きいが、どの読み手でも開ける。
（[overview.md](overview.md) の「外部ライブラリには依存しない」）

## 宣言的な層

「どう描くか」ではなく「**いまどうあるべきか**」を書く。
部品を作って `ui.col` などに**組んで1つ返す**と、そのとおりに描かれる。

くり返しも描き直しも `ui.run()` が引き受ける。**押されたときの動きは、部品に持たせる。**

```shark
var count = 0;                        // 状態はふつうの変数

func view() -> Widget {               // いまどうあるべきか
  return ui.col([                     // 縦に並べる
    ui.label(f"{count} 回"),
    ui.button("ふやす", func() -> void { count += 1; }),   // ← 動きをその場に書く
  ]);
}

func main() -> int {
  ui.run("かうんた", 420, 300, view);
  return 0;
}
```

動きは名前を付けた関数でもよい（`func inc() -> void { count += 1; }` を作って
`ui.button("ふやす", inc)`）。その場に書く形は [../syntax.md](../syntax.md) にある。

関数のほかに、**名札**（`id`）でも受け取れる。まとめて振り分けたいときはこちら。

```shark
ui.button("ふやす", "inc")            // ui.show() が "inc" を返す

func update(hit: string) -> void {
  if hit == "inc" { count += 1; }
}
ui.run("かうんた", 420, 300, view, update);
```

どの形も、末尾に `false` を足すと**大きさの変わらない窓**になる
（`ui.run("かうんた", 420, 300, view, update, false)`）。省くと変えられる。

部品の呼び名は、よく使われているものに合わせてある。探すときの手がかりに。

| | 通りのいい名前 | | 通りのいい名前 |
|---|---|---|---|
| `ui.label` | ラベル | `ui.field` | テキストフィールド |
| `ui.button` | ボタン | `ui.textarea` | テキストエリア |
| `ui.checkbox` | チェックボックス | `ui.password` | パスワード欄 |
| `ui.radio` | ラジオボタン | `ui.combo` | **プルダウン**（コンボボックス） |
| `ui.slider` | スライダー | `ui.listbox` | リストボックス |
| `ui.number` | 数の入力欄（スピンボックス） | `ui.tabs` | タブ |
| `ui.divider` | セパレータ | `ui.grid` | グリッド（表） |
| `ui.spacer` | スペーサー | `.tooltip` | ツールチップ |
| `ui.col` / `ui.row` | 縦・横の並び | `.placeholder` | プレースホルダ |
| `ui.stack` | 重ね置き（ZStack） | `ui.scroll` | スクロールビュー |

**値を持つ部品は、変数を `ref` で渡すのがいちばん短い。**動いたらその変数が
直に書き換わるので、名札も `update()` も `ui.value()` も要らない。

| | ref を渡す | 関数を渡す | 名札を渡す |
|---|---|---|---|
| `ui.button` | — | `ui.button(label, f)` | `ui.button(label, id)` |
| `ui.checkbox` | `ui.checkbox(label, ref on)` | `ui.checkbox(label, f, on)` | `ui.checkbox(label, id, on)` |
| `ui.radio` | `ui.radio(label, ref v, mine)` | `ui.radio(label, f, on)` | `ui.radio(label, id, on)` |
| `ui.slider` | `ui.slider(ref v, lo, hi)` | `ui.slider(f, v, lo, hi)` | `ui.slider(id, v, lo, hi)` |
| `ui.number` | `ui.number(ref v, lo, hi)` | `ui.number(f, v, lo, hi)` | `ui.number(id, v, lo, hi)` |
| `ui.field` | `ui.field(ref value)` | — | `ui.field(id, value)` |
| `ui.textarea` | `ui.textarea(ref value)` | — | `ui.textarea(id, value)` |
| `ui.password` | `ui.password(ref value)` | — | `ui.password(id, value)` |
| `ui.combo` | `ui.combo(ref i, options)` | `ui.combo(f, options, i)` | `ui.combo(id, options, i)` |
| `ui.listbox` | `ui.listbox(ref i, options)` | `ui.listbox(f, options, i)` | `ui.listbox(id, options, i)` |
| `ui.tabs` | `ui.tabs(ref i, labels)` | `ui.tabs(f, labels, i)` | `ui.tabs(id, labels, i)` |

```shark
var sound = true;                    // 一番外側の var（下の「ref で渡せるもの」）
var volume = 60;

ui.checkbox("音を出す", ref sound)   // 押されるたびに sound が入切する
ui.slider(ref volume, 0, 100)        // 動かすたびに volume が書き換わる
```

**これでも部品は状態を持たない。**値は今までどおり呼んだ側の変数にあり、処理系が
覚えるのは「どの var か」（一番外側の var の番号）だけ。書き戻しはその var への
代入と同じで、次の回の `view()` はその変数を読み直す。だから画面と食い違わない。

ボタンのように値を持たないものは、動きをその場に書く。値を持つ部品に関数を
渡したときは、新しい値をその中で `ui.value()` から読む。

名札を付けて `update()` で振り分ける形も残してある。その場に書いた関数からは
外側の局所変数が見えないので、**升ごとに作るもの**（`ui.grid(rows, cols, cell)`）
などはこちらになる。混ぜてよい。

`ui.run()` の中身はこれだけ。

1. 面を開く（細かい画面なら細かく取り、字も読む）
2. 押された・動いた を取り込む
3. `view()` を呼んで、そのとおりに描く
4. 押された部品が関数を持っていれば**それを呼び**、名札なら `update()` を呼ぶ。
   `ref` で受けた入力欄は `ui.show()` の中で変数を書き換えている（`ui.edited()`）。
   どれかが起きていれば、そのあと**その場で描き直す**
5. 窓が閉じられるか `ui.quit()` まで、2 に戻る

**状態を持つのは書く人だけ。**処理系は覚えない。だから「いまの状態」と「画面」が
食い違いようがない。部品も毎回作り直され、状態を持たない。

`ui.run()` は **Shark 自身で書いてある**（`stdlib/prelude_ui.shk`）。
処理系の中に特別な仕掛けがあるわけではなく、下の層を呼んでいるだけなので、
足りなければ同じことを自分で書けばよい。

```shark
ui.open("さかな", 160, 120);
while ui.poll() {
  ui.clear();
  var hit = ui.show(view());
  var changed = ui.edited();                    // ref で受けた入力欄が書き換えた
  if ui.has_action() { var act = ui.action(); act(); changed = true; }
  if hit != "" { update(hit); changed = true; }
  if changed { ui.clear(); _ = ui.show(view()); }
  ui.present();
  ui.frame();
}
ui.close();
```

部品が持っている関数を**呼ぶのは Shark の側**。ネイティブから Shark の関数は
呼び戻せないので、`ui.show()` は「押された部品が持っていた関数」を覚えておくだけにして、
`ui.action()` で取り出して呼ぶ形にしてある。

画面が無いところ（`SHARK_UI=off`）では、`ui.run()` は**1回だけ描いて返る**。
面はそのままなので、`ui.get()` や `ui.to_png()` で結果を確かめられる。

### ref で渡せるもの

`ui.field(ref ...)` に渡せるのは**一番外側の `var`** だけ。ほかは型検査が断る（E0307）。

```shark
var name = "";                     // ← ここに置く

func view() -> Widget {
  var tmp = "";
  return ui.field(ref tmp);        // 誤り E0307: view() が返ると tmp は消える
}
```

ほかのモジュールの `var`（`state.name`）も一番外側の var なので渡せる。

`ref` はふつう「呼んでいる間だけの借用」だが、これはその例外ではない。
処理系が覚えるのは借用（指し先）ではなく **どの var か**（番号）だけで、
書き戻しはその var への代入と変わらないため（[../runtime/memory.md](../runtime/memory.md)）。
番号にできるのは一番外側の var だけ、というのが上の決まりの理由。書き戻すのは `ui.show()` の中。

宣言的な層では、状態はどのみち一番外側の `var` に置くことになる。その場に書く関数からも
外側の局所変数は見えないため（[../syntax.md](../syntax.md)）、この決まりで困ることは少ない。

### なぜ配列なのか

宣言的な UI は、ふつう**呼び出しにブロックを続ける記法**で書く。

```
ui.column {          // ← この書き方は Shark の構文には無い
  ui.text("...");
}
```

Shark にはその記法が無く、入れるとなると構文・型検査・`ref` の捕まえ方まで
決め直すことになる（下書きは [ui-declarative.md](ui-declarative.md)）。

入れ物（`ui.col` / `ui.row` / `ui.grid`）に**配列で渡す**形なら、**いまの言語のまま**
同じことが書ける。しかも UI が値になるので、

- `view()` は**ただの関数**。引数から部品を組んで返すだけで、副作用が無い
- `if` や `for` で組み立てられる。並びを作るのに特別な書き方が要らない
- 中身を変数に入れて回せる。テストで組み立てだけを確かめることもできる

`view()` が返すのは**部品1つ**。いくつも並べるときは入れ物に入れて1つにする。
いちばん外が入れ物でなくてもよい（`return ui.label("さめ");`）。

### 名札で受け取る

`ui.show()` が返すのは、**この回に動いた部品の名札**（`id`）。
何も起きていなければ空の文字。

| 部品 | 名札が返るとき | 新しい値 |
|---|---|---|
| `ui.button(label, id)` | 押されたとき | — |
| `ui.checkbox(label, id, on)` | 押されたとき | `ui.value()` が 1 か 0 |
| `ui.slider(id, value, lo, hi)` | つまんでいる間 | `ui.value()` が選ばれた数 |
| `ui.field(id, value)` | 打たれたとき | `ui.text_value()` が新しい文字 |
| `ui.field(ref value)` | 返らない（変数を直に書き換える） | 渡した変数がそのまま新しい文字 |
| `ui.textarea(id, value[, rows])` | 打たれたとき | `ui.text_value()` が新しい文字 |
| `ui.textarea(ref value[, rows])` | 返らない（変数を直に書き換える） | 渡した変数がそのまま新しい文字 |
| `ui.password(...)` | `ui.field` と同じ | 同じ（伏せるのは**出すときだけ**） |
| `ui.radio(label, id, on)` | 押されたとき | `ui.value()` が 1 |
| `ui.number(id, v, lo, hi)` | 数が変わったとき | `ui.value()` が新しい数（`lo`〜`hi`） |
| `ui.combo(id, options, i)` | 一覧から選ばれたとき | `ui.value()` が選ばれた番号 |
| `ui.listbox(id, options, i[, rows])` | 選ばれたとき | `ui.value()` が選ばれた番号 |
| `ui.tabs(id, labels, i)` | 別のタブが押されたとき | `ui.value()` が押された番号 |
| `ui.label(text)` | 返らない | — |
| `ui.space(h)` / `ui.spacer([size])` / `ui.divider()` | 返らない | — |
| `ui.col(kids)` / `ui.row(kids)` / `ui.grid(cols, kids)` / `ui.center(kids)` | 中身のものが返る | — |
| `ui.stack(kids)` / `ui.scroll([id, ]kids)` | 中身のものが返る | — |

**部品は状態を持たない。**値は呼んだ側が持ち、毎回渡し直す。

```shark
if hit == "sound" { sound = ui.value() == 1; }
```

こうすると「いまの状態」と「画面に出ているもの」が食い違わない。
チェックが入っているのに変数が `false`、という組み合わせがそもそも作れない。

### 並べ方

`ui.col` は縦に、`ui.row` は横に並べる。入れ子にできる。

```shark
ui.row([
  ui.col([ui.label("左上"), ui.label("左下")]),
  ui.col([ui.label("右上"), ui.label("右下")]),
])
```

**重ね置き**（`ui.stack`）は、中身を同じところに重ねる。書いた順にあとのものが上に来て、
大きさはいちばん大きい中身に合わせる。置き場所は中身ごとの `.align`（横）と `.valign`（縦）で決め、
書かなければ左上。絵の上に字を出す、下地の上にボタンを置く、といったときに使う。

**巻物**（`ui.scroll`）は、中身を縦に並べ、はみ出したぶんを送って見る入れ物。
`.height(n)` で高さを決めると、そこに入りきらないぶんが隠れて右に帯が出る。
帯はつまんで動かせ、上に載せていれば車輪（ホイール）でも送れる。
高さを決めなければ、中身のぶんだけ伸びて巻かれない。
**隠れているところは押されない**（見えていないものを押せてしまわない）。
送ったところは名札ごとに覚えていて、次の回も同じところが出る。

格子は `ui.grid(列の数, 升の配列)`。升は左上から右へ、いっぱいになれば次の行へ詰める。
**列の幅はその列でいちばん広い升、行の高さはその行でいちばん高い升に揃う**ので、
`ui.row` を `ui.col` に重ねたときと違って、縦の線が通る。
升ごとの関数から作る形（`ui.grid(行, 列, cell)`）もあり、`cell(行, 列)` が返す部品を同じ順に詰める。

```shark
ui.grid(3, [ui.button("7", "7"), ui.button("8", "8"), ui.button("9", "9"),
            ui.button("4", "4"), ui.button("5", "5"), ui.button("6", "6")])

func key(r: int, c: int) -> Widget { return ui.button(f"{r * 3 + c}", f"{r * 3 + c}"); }
ui.grid(3, 3, key)                  // 同じものを関数から
```

関数から作る形は **Shark で書いてある**（`stdlib/prelude_ui.shk`）。ネイティブからは Shark の
関数を呼び戻せないので、升を作る関数を呼ぶところは Shark の側に置き、並べるところだけを
ネイティブの `ui.grid(列の数, 升)` に渡している。

大きさは中身から決まる（文字の長さ、部品の決まった高さ）。
指定するのは `ui.show(view, x, y)` の置き場所だけで、それも省くと (4, 4) から。

長い文（`ui.label`）が置ける幅に入らないときは、**折り返して**何行かになる。
折り目はその行の空白（英語の単語を切らない）、無ければ（日本語など）入り切らない字の手前。
置ける幅は、親がくれた幅か `.width(n)` で決めた幅。
`ui.row` の中では `.width(n)` を書いたときだけ折り返す（横に並ぶ幅は中身から決まるため）。
下の層の `ui.text()` は折り返さない（あちらは置いた場所にそのまま描くだけ）。

入れ物の大きさは**中身に合わせて伸び縮みする**。`ui.col` なら幅はいちばん広い子、
高さは子の合計で、`ui.row` はその逆。だから `.background()` も中身のぶんだけ塗られる。
広げたいときは、取り分（`.width(1.0)` など）か画素（`.width(n)`）を書く。

**いちばん外（`ui.show()` に渡した部品）だけ**は、寄せていなければ置ける幅いっぱいに広がる。
だからいちばん外の並びでは、区切り線（`ui.divider`）や寄せ（`.align("right")`）が面の幅を見る。
寄せた入れ物（`ui.center` もその1つ）は中身の大きさのまま、**かたまりとして**寄る。

### 見た目を1つずつ変える

部品ごとに変えたいときは、**メソッドをつないで**書く。

```shark
ui.label("さめ").color(ui.rgb(255, 200, 0)).background(ui.rgb(30, 30, 40)).padding(6)
```

| メソッド | |
|---|---|
| `.color(c)` | 文字の色 |
| `.background(c)` | 下地の色。部品の後ろを塗る |
| `.border(c[, w])` | 縁の色と太さ（画素）。太さを省くと 1 |
| `.radius(n)` | 角の丸み（画素）。下地にも縁にも効く |
| `.padding(n)` | 内側の余白（画素） |
| `.width(n)` / `.height(n)` | 大きさを決める。**int なら画素、float なら取り分**（下）。決めなければ中身から決まる |
| `.align(a)` | 親がくれた幅の中で寄せる。`"left"` `"center"` `"right"` |
| `.valign(a)` | 親がくれた高さの中で寄せる。`"top"` `"middle"` `"bottom"` |
| `.tooltip(t)` | カーソルを合わせたときに出す説明。少し待つと出る（下） |
| `.placeholder(t)` | 入力欄が空のときに、うすく出しておく字（下） |

縁は**中身のあとに引く**ので、細い線でも中身に隠れない。`.radius()` と一緒に書けば、
下地も縁も同じ丸みに沿う。

取り分（fr）は、**親がくれた場所の余り**を、並んだ仲間と比で分けるもの。
`.width(1.0)` と `.width(2.0)` なら余りを 1:2 に、`float.infinity()` は「余りぜんぶ」。

入れ物（`ui.col` / `ui.row` / `ui.grid`）がその向きの大きさを決めていなければ、
中の部品の取り分は**入れ物ごしに外まで効く**。row の中のボタンに書くだけで、
その row が col の余りを取り、ボタンが窓の下まで伸びる。
入れ物に画素の大きさ（`.height(n)`）か入れ物自身の取り分を書くと、そちらが勝つ。

```shark
ui.col([
  ui.label("上"),
  ui.row([ui.button("a", "a"),
          ui.button("b", "b").height(float.infinity())]),   // row も一緒に、余りまで広がる
])
```

入れ物の受け継ぎ方は、伸び縮みと同じ考え方。重なる向き（col の幅、row の高さ）は
いちばん大きいもの、積み上がる向き（col の高さ、row の幅）は合計、
格子は列（行）ごとのいちばん大きいものの合計になる。

**返るのは変えたもので、元は変わらない。**「すべての代入はコピー」と同じ考え方
（[../types/class.md](../types/class.md)）。だから元を使い回せる。

```shark
var base = ui.label("さめ");
var red = base.color(ui.rgb(255, 0, 0));   // base は変わらない
```

寄せ方は「**親がくれた幅の中で、自分をどこに置くか**」。いちばん外側でくれる幅は、
`ui.show(view, x, y)` の x から見て面に残っているぶん（面の幅 − x × 2）。

```shark
ui.label("まんなか").align("center")     // 面の真ん中に置く
ui.center([ui.label("これも"), ui.label("まんなか")])   // まとめて真ん中に
```

### 見た目の既定値

`ui.theme(bg, fg, accent)` で3色だけ決める。部品の色はそこから作られる。

寸法はすべて**字の大きさ**（内蔵なら 8、`ui.font(18)` なら 18）に対する比で決まる。
フォントを変えても、細かい画面で字を大きくしても、そのまま釣り合う。

| 決めていること | 字の大きさに対して | 内蔵のとき |
|---|---|---|
| 縦に並べたときの間 | 1/2 | 4 画素 |
| 横に並べたときの間 | 3/4 | 6 画素 |
| ボタン・入力欄の内側の余白 | 横 5/8・縦 3/8 | 5・3 画素 |
| チェックの四角・ラジオの丸 | 行の高さの 7/8（9 画素より小さくしない） | 9 画素 |
| つまみの長さ | 12 倍 | 96 画素 |
| 入力欄の長さ | 15 倍 | 120 画素 |
| 入力欄のカーソルの太さ | 1/8 | 1 画素 |
| 複数行の入力欄の高さ | 行の送り × 行数 ＋ 余白 | 4 行なら 38 画素 |
| 同じく、右に空ける帯の幅 | 1/4（3 画素より狭くしない） | 3 画素 |
| 色 | 下地 `#14141C`、文字 `#E6E6E6`、差し色 `#4C9BE8` | |

寸法を1つずつ指定する仕組みは持たない。細かく決めたいものは、
下の層で自分で描く方が早いため。

### 入力欄

`ui.field` は押すとそこに文字が入るようになる。打たれた文字の受け取り方は2つ。

```shark
ui.field(ref name)         // name が直に書き換わる
ui.field("name", name)     // ui.show() が "name" を返し、ui.text_value() が新しい文字
```

どちらでも、文字を持つのは書く人の変数。処理系は覚えない。

- 消すのは `back`、離れるのは `enter`
- ただし**変換中の `enter` は「確定」**なので、入力欄からは出ない。
  出るのは、何も変換していないときの `enter`
- 日本語などの変換は出し先に任せる（上の「日本語などの入力」）
- 出せる字は、そのときの字の出どころ次第（内蔵なら ASCII だけ）

### 複数行の入力欄

`ui.textarea` は、`ui.field` と同じものの**複数行版**。受け取り方も同じ2つ。

```shark
ui.textarea(ref memo)         // memo が直に書き換わる
ui.textarea(ref memo, 8)      // 8 行ぶんの高さで出す（省くと 4 行）
ui.textarea("memo", memo)     // ui.show() が "memo" を返す
```

中身は**改行（`\n`）を持つ1つの文字列**。行に分けるのは書く人の側
（`memo.split("\n")`）で、処理系は行の一覧を持たない。ここも「値は呼んだ側が持つ」。

- `enter` は**改行を入れる**（`ui.field` は入力欄から離れる）。離れるのは、外を押すか `esc`
- 置ける幅に入らない行は**折り返して**出る。折り目は `ui.label` と同じ
  （その行の空白、無ければ字の手前）。折り返しても中身の文字列は変わらない
- 上下の矢印で行を行き来する。`home` と `end` はその行の端、`pageup` と `pagedown` は1画面ぶん
- 行が入りきらないときは、右に今どのあたりかの帯が出る
- 選ぶ・切り貼り・変換は `ui.field` と同じ（下）

**行にまつわるキー（`enter`・上下・`home`・`end`）は、コアが受け持つ。**
折り返す幅を知っているのはコアの側だけで、移植層の受け皿（macOS の `NSTextView`、
ブラウザの `<textarea>`）に渡すと、**向こうの折り返し方でもう一度動いてしまう**ため。
移植層には「複数行か」を伝えるだけで（`platform.h` の `text_input` の `multiline`）、
受け皿は改行を落とさずに持ち、これらのキーは自分では扱わない。

#### 何も入っていないとき（プレースホルダ）

`.placeholder(text)` を付けると、入力欄が空のあいだ、その字がうすく出る。
1字でも打てば消える。**出しているだけ**なので中身にはならず、`ui.text_value()` や
`ref` で渡した変数は空のまま。伏せ字の欄でも、この字は伏せない。

#### 枠より長い中身

入力欄は左を隠して見せる（`ui.field`）か、折り返す（`ui.textarea`）。
どちらも**枠の外には描かない**。1行の入力欄でカーソルを左へ戻すと、
その後ろの字は枠より右に伸びるので、そこで切る。

### 伏せ字の入力欄

`ui.password` は `ui.field` と同じもので、**出すときだけ**1字を1つの `*` に置き換える。
`ui.text_value()` や `ref` で渡した変数には、打たれた字がそのまま入る。

右で押したときのメニューに、コピーと切り取りは出ない（中身が持ち出せてしまうため）。
貼り付けとすべて選ぶは出る。

#### 選ぶ・切り貼り

| すること | やり方 |
|---|---|
| 場所を決める | 押す。矢印でも動く |
| 選ぶ | なぞる。shift を押しながら矢印でも選べる |
| 語を選ぶ | **2回続けて押す**（空白から空白まで。日本語は書かれたひと続き） |
| 行を選ぶ | **3回続けて押す**（折り返しではなく、書かれた改行まで） |
| ぜんぶ選ぶ | **4回続けて押す** |
| 取り消す | Cmd-Z（Windows・Linux は Ctrl-Z） |
| やり直す | Shift-Cmd-Z（Ctrl-Y でも同じ） |

取り消し帳は**コアが持つ**。受け皿（macOS の `NSTextView` など）の取り消しに頼ると、
機種ごとに別物になるうえ、こちらが中身を入れ直したときに食い違う。
控えるのは「変わる前の中身とカーソル」で、**続けて打った字は 0.5 秒のあいだ
1回ぶんにまとめる**（1字ずつ戻るのは戻しすぎ）。焦点が別の入力欄に移ると忘れる。
| 切り貼り | 右で押すと出るメニュー（コピー・切り取り・貼り付け・すべて選ぶ） |
| 同上（窓・macOS） | Cmd-C / Cmd-V / Cmd-X / Cmd-A も効く |
| 同上（窓・Windows） | ctrl+C / ctrl+V / ctrl+X / ctrl+A も効く |

続けて押したと数えるのは、**同じ入力欄の近いところ（3 画素）を 0.45 秒のうちに**
押したとき。数え直しはそこで切れる。

選んでいるところは、**移植層が持っていればそちらが正**。
macOS の窓では OS の入力欄が持っているので、二度押しでの単語選びや取り消し（Cmd-Z）も
そのまま効く。Windows の窓では移植層が中身と選んでいるところを持つ。
持たない出し先では、コアが文字の数を覚えて動かす。

切り貼りの置き場（クリップボード）は `ui.clipboard()` と `ui.set_clipboard()` で
プログラムからも触れる。持たない出し先では空が返る。

#### 入切のしるし

- チェック … 四角い枠と、**枠の真ん中**に置いたレ点。**中は塗らない**
  （塗ると印が読みにくく、並べたときに重い）。入っているかは、枠の濃さと印の有無で分かる
- ラジオ … 差し色の輪と、真ん中の点。四角と丸で、択一かどうかがひと目で分かる

大きさは**字の高さに合わせる**。字より小さいと、並べたときに沈んで見えるうえ、
押しにくい。レ点の太さも長さも箱の大きさから決めるので、字を大きくしても釣り合う。

置く高さは、行の箱の真ん中ではなく**字の見た目のまんなか**に合わせる。
字を出すのは「行の箱」の位置指定で、字のインクはその中で下に寄っている
（上に行間があく）ので、行の箱で揃えると印だけ上にずれて見える。
大文字（`H`）の高さの真ん中を取って、そこに印の中心を置く。

#### つまみ

`ui.slider` は、**つかんだら離すまで付いてくる**。押しっぱなしで動かすものが
部品の外に出たとたん止まると、行き過ぎたときに戻せなくなって使いにくい。
どのつまみをつかんでいるかは、名札（無ければ ref で受けた var、それも
無ければ置かれた場所）で見分ける。

通ってきたところは差し色で塗る。いまどのあたりかが、つまみの位置だけより読み取りやすい。

### 選ぶ部品

「いくつかの中から1つ」を選ぶ形は3つある。どれも並べるものは `list<string>` で渡し、
**選ばれた番号**（0 から）が `ui.value()` で返る。番号を持つのは呼んだ側。

| 部品 | 通りのいい名前 | 見た目 | 向いているところ |
|---|---|---|---|
| `ui.radio` | ラジオボタン | 丸を並べる | 2〜4 個くらい。ぜんぶ見せたいとき |
| `ui.combo` | プルダウン（コンボボックス） | 押すと一覧が出る | 数が多くて、ふだんは隠しておきたいとき |
| `ui.listbox` | リストボックス | 一覧が出たまま | 数が多く、見比べながら選びたいとき |

`ui.radio` だけは「自分が選ばれているか」を `bool` で渡す（`ui.checkbox` と同じ形）。
どれが選ばれているかを持つのは呼んだ側なので、これでよい。

`ui.combo` の一覧は、メニュー（下）と同じ仕組みで出す。押した部品と同じ幅で、その下に開く。
選び方は2つあり、どちらでもよい。

- 押して離すと出たままになる。そのあともう一度押して選ぶ
- **押したまま下へ動かし、選びたいところで離す**（プルダウンのふつうの選び方）

`ui.listbox` は入りきらないときに右へ帯を出す。**帯はつまんで動かせる**ので、
選んでいるものから離れたところも見に行ける。押して焦点が来ているあいだは
上下の矢印でも選べ、そのときは選んだものが見えるところまでひとりでに送る。

巻物を持つ部品（`ui.listbox`・`ui.textarea`・`ui.combo` の一覧）は、
**カーソルが乗っていれば車輪（ホイール）でも送れる**。押していなくてもよい。
その回の送りぶんは部品が使い切るので、`ui.wheel()` は 0 になる
（部品と、自分で書いた巻物とが二重に動かない）。

### 巻物のなめらかさ

巻物の位置は**行の数ではなく画素**で持つ。行で持つと、送るたびに1行まるごと飛んで
**途中が出ない**（どこへ動いたのかが分からない）。

いま（`cur`）と目当て（`to`）の2つを持ち、毎こま `cur` を `to` へ寄せる。
寄せ方は「残りの 2/5 ずつ、端数は1画素ずつ」で、60 こま／秒なら 0.2 秒たらずで着く。
そのあいだ、上と下には**半端に切れた行**が出る。

その場で合わせる（寄せない）のは3つ。

- 帯をつまんでいる間 … 指に付いてくるべきなので
- 入力欄で字を打っている間 … 間が空くと読みにくいので
- その部品を**初めて出す回** … 画面の無いところ（1回しか描かない）でも、
  正しいところが出るように

巻物の位置を覚えているのは**最後に触った一覧のぶんだけ**で、部品そのものは覚えない。
帯でずらしたあと、選が変わっていないのに選のところへ戻ってしまわないよう、
「見えるところまで送る」のは**選が変わった回だけ**にしてある。

### 空き場所

`ui.spacer([size])` は**並んでいる向き**に場所を取る。`ui.row` の中なら横、
`ui.col` の中なら縦。数を省くと、**余ったところをぜんぶ取る**（伸びる空き）。

```shark
ui.row([ui.label("なまえ"), ui.spacer(), ui.button("消す", "del")])   // 右端へ
ui.row([ui.spacer(), ui.label("まんなか"), ui.spacer()])              // 真ん中へ
```

向きは、入れ物が置くときに立てる印を見て決める（`core/lib/ui.cpp` の `g_row_axis`）。
測るとき・置くとき・取り分を数えるときで同じ向きを見ていないと大きさが食い違うので、
入れ物はどこでもこの印を立て直す。

伸びる形は、取り分（fr）の「余りぜんぶ」と同じ仕組みに乗せてある。だから
2つ以上置けば余りを等分するし、`.width(float.infinity())` と混ぜても筋が通る。

`ui.space(h)` は**縦にしか**空けない（前からあるもの）。横に並べたときにも
効かせたいときは `ui.spacer` を使う。

### タブ

`ui.tabs(id, labels, index)` は**見出しだけ**を出す。中身は呼んだ側が選んで返す。

```shark
ui.col([
  ui.tabs("tab", ["メモ", "いろ"], tab),
  body(),        // tab を見て、いまの中身を組む
])
```

中身まで抱えないのは、「いまどうあるべきか」を返すという書き方に合わせるため。
見出しと中身が別なので、中身をどこに置くかも呼んだ側が決められる。

### 数の入力欄

`ui.number(id, value, lo, hi)` は、**`lo` から `hi` の外に出られない**入力欄。

- 打てるのは数字だけ（`lo` が負のときは、先頭の `-` も）
- **限りから出る数は打っても入らない。**だから範囲の外の値になることがない
- 右の − と ＋、上下の矢印でも 1 ずつ動く
- 打っている途中は「まだ数になっていない形」（空や `-` だけ）も通る。
  その字だけは焦点のあるあいだ処理系が持つ（巻物の位置と同じ、**見た目のための覚え**）。
  値そのものは、いつもどおり呼んだ側が持つ

### 説明（ツールチップ）

どの部品にも `.tooltip(text)` を付けられる。カーソルを合わせて **0.4 秒**待つと、
そのそばに出る（すぐ出すと、通りすがりで点滅して読みにくい）。長い文は折り返す。
入れ子にしたときは、**細かいほう**（中身）の説明が出る。

画面が無いところ（`SHARK_UI=off` など）では待たずに出す。1回しか描かないため。

### メニュー

`ui.menu(x, y, items)` で、その場所に一覧を出す。選ばれるか、外を押されるまで出たまま。

```shark
if ui.clicked(2) { ui.menu(ui.mouse_x(), ui.mouse_y(), ["消す", "やり直す"]); }
var pick = ui.menu_pick();
if pick == 0 { erase(); }
```

- **押されたところはメニューが先に受け取る。**下にある部品は反応しない
- 入力欄が出すメニューには、**キーの押し方を右にうすく出す**（`Cmd+C` / `Ctrl+C`）。
  どちらで書くかは、機種の名前（`os.name()`）で決める
- 描くのはいちばん上。面からはみ出すときは中に寄せる
- 入力欄は、右で押すと**自分で切り貼りのメニューを出す**ので、書かなくてよい

面に入りきらないときは、**上と下に送るしるし（▲▼）**を付けて巻物にする。
そこにカーソルを合わせているあいだ、0.06 秒に1つずつ送る（押したまま端まで
動かしても送れる）。しるしを押しても閉じない。**車輪（ホイール）でも送れる。**

**離したところでも決まる。**押したまま動かして項目の上で離すと、それが選ばれる。
出したところ（部品の上）で離しただけなら、出たままにする。こうすると
「押して離して、もう一度押す」と「押したまま動かして離す」のどちらでも選べる。

右で押して出したメニュー（`ui.clicked(2)` から出すものや、入力欄の切り貼りメニュー）も、
**同じ右のまま動かして離すと選べる**。出したその場でほとんど動かさずに離しただけなら、
選んだことにはしない（出す押しがそのまま項目の上に乗ることがあるため）。

### 自分で部品を作る

上の層で足りなければ、下の層で描けばよい。ボタンは、四角と文字を描いて、
マウスが中にあるかを見るだけで作れる。

```shark
func button(x: int, y: int, w: int, h: int, label: string) -> bool {
  var mx = ui.mouse_x();
  var my = ui.mouse_y();
  var over = mx >= x && mx < x + w && my >= y && my < y + h;
  var bg = ui.rgb(40, 50, 70);
  if over { bg = ui.rgb(70, 90, 120); }
  ui.fill_rect(x, y, w, h, bg);
  ui.text(x + (w - ui.text_width(label)) / 2, y + (h - ui.text_height()) / 2,
          label, ui.rgb(240, 240, 240));
  return over && ui.clicked(0);
}

if button(10, 10, 60, 16, "start") { start(); }
```

「今そのとき押されたか」を毎回作り直して答える形なので、
部品の状態をどこかに覚えておく必要がない。`ui.show()` の中もこれと同じことをしている。

## 移植層に求めるもの

`PlatformScreen`（[../runtime/platform.md](../runtime/platform.md)）。無くてもよい。

| | |
|---|---|
| `scale()` | 画面の細かさ（HiDPI なら 2）。**開く前にも答えること** |
| `open(title, w, h)` | 出せないなら `false`。そのとき見えない面になる |
| `close()` | 片付ける |
| `present(px, w, h)` | 画素の並びを画面に出す。1つが `0x00RRGGBB` |
| `poll(&event)` | 出来事を1つ渡す。無ければ `false`。**待たない** |
| `has_key_up` | 「離した」を出せるか |
| `text_input` / `text_state` | 変換つきの文字入力（IME）。無くてよい |
| `text_selection` / `text_select` / `text_replace` | 選んでいるところ。無ければコアが数える |
| `clipboard_get` / `clipboard_set` | 切り貼りの置き場。無ければ空 |
| `set_cursor(kind)` | マウスの形を変える（`ui.cursor()`）。変わったときだけ呼ばれる。無くてよい |
| `set_redraw(fn)` | 縁を引いている間 OS がプログラムを止める機種で、コアに絵の出し直しを頼む口。無くてよい |
| `set_resizable(on)` | `false` で大きさの変わらない窓にする。`open` のすぐあとに呼ばれる。無くてよい |

面の大きさと画面の大きさが違うときは、**移植層が引き伸ばす**。
マウスの位置は、面の中の画素に直してから渡す。
どこまで引き伸ばすかは機種の事情なので、コアは口を出さない。

引き伸ばすのは、**広げても 320×240 に収まる面**だけにする。
それより大きい面は、画面の画素と1対1にする。そうしないと、
細かい画面のために細かく取った面が、もう一度引き伸ばされてしまう。
書いた側が思ったとおりの細かさで出るほうが、粗いまま大きく出るより良い。

窓の大きさを変えられる出し先では、変わったときに `SEV_Resize`（`x`, `y` に新しい面の
画素数）を1つ渡す。コアはそれを受けて面を作り直す（上の「窓の大きさを変えたとき」）。

車輪（ホイール）を持つ出し先は `SEV_Wheel` を渡す。`x`, `y` は**送りぶん（1/100 行）**で、
下と右が正（1段ぶん回すと 100）。機種によって届く単位がまちまち（Windows は 120 の倍数、
トラックパッドは点）なので、**行に直すのは移植層の仕事**。

**行より細かく渡せるようにしてある。**行の数で渡すと、トラックパッドをゆっくり
動かしたときに1行たまるまで何も動かず、動き出すと1行飛んでしまう。
段でしか送れない機種（車輪だけのマウス、X11）は 100 の倍数で渡せばよい。
1画素に満たないぶんを持ち越すのはコアの側。無くてよい。
渡さない機種では、面は開いたときの大きさのまま変わらない。
`ui.open(..., false)` と頼まれた窓は大きさが変わらないので、`SEV_Resize` も来ない。

### `shark` コマンドの場合

窓を開く。開けなければ画面なしになる。

| 順 | 出し先 | どうやって |
|---|---|---|
| 1 | 窓（macOS） | AppKit。窓の中身は `CGImage` にして層に貼る |
| 1 | 窓（Windows） | Win32 と GDI。画素の並びをそのまま `StretchDIBits` で貼る |
| 1 | 窓（Linux ほか） | X11。画素の並びをそのまま `XPutImage` で置く |
| 2 | 画面なし | 見えない面に描く |

**窓の道具（GUI ツールキット）には頼らない。**必要な関数は
**実行時に**取りに行く（`dlopen` / `LoadLibrary`）ので、作るときに要るライブラリは無い。
X11 の入っていない機械でも、そのまま作って動く（窓が開かないだけ）。

- マウスの形は、macOS は `NSCursor`、Windows は `LoadCursor`、X11 は `XCreateFontCursor`
- 窓の大きさは面の整数倍。拡大しても画素の形は崩さない
- 窓の縁を引くと `SEV_Resize` が届き、面も同じ大きさに作り直される
- 窓を閉じると `ui.poll()` が `false` を返す。macOS では Cmd-Q も同じ
- 面より画面が大きいときに広げるのは**移植層**の仕事。コアは口を出さない

環境変数 `SHARK_UI` に `off`（`none` も同じ）を入れると、窓を試さずに
画面なしにできる。テストと `make docs-check` はこれにしてある。窓が開くと、
結果が機種によって変わってしまうため。

### ブラウザの場合

**窓を出す。**帯・× ・隅の持ち手をこちらでこしらえ、中身は `canvas` に流し込む
（`core/platform/screen_canvas.inc`。[../../web/README.md](../../web/README.md) の「画面」）。
見た目は Dear ImGui に寄せてある ― 角は立てたまま、細い縁、濃い青の帯（触っていない
ときは黒に近くなる）、右下に三角の持ち手。帯の ▼ でたためる。

| もの | どうしているか |
|---|---|
| 出す先 | 窓をこしらえて `body` に置く。ページの中に埋め込みたいときは `Module.sharkMount` か `#shark-screen` を置く（そこには面だけ出る） |
| 引き伸ばし | 面の1画素は画面の1画素。切手のように小さい面（広げても 320×240 に収まるもの）だけ整数倍にし、入りきらなければ縦横の比を保って縮める |
| 細かさ | `ui.scale()` は `devicePixelRatio` |
| 大きさ | 隅の持ち手を引くと `SEV_Resize`。窓の縁を引くのと同じ（`ui.open(..., false)` なら持ち手を出さない） |
| キー・マウス | `keydown` / `keyup` と `pointer*`。指で触っても同じように届く |
| 文字入力 | 見えない `textarea` に任せる。**かな漢字変換はブラウザのものがそのまま使える** |
| 閉じる | 窓の × で `SEV_Close`（ホストからは `requestClose()`） |
| マウスの形 | CSS の `cursor`（`pointer` `text` `crosshair` …）。`none` は消す |
| 字 | ブラウザに1文字ずつ描いてもらい、濃さを写し取る（`core/platform/font_canvas.inc`）。**日本語もそのまま出る** |

`document` が無いところ（node で動かしたとき）と `SHARK_UI=off` では開かず、見えない面に描く。

### ゲームに組み込む場合

面はゲーム本体が受け取り、ゲームの画面の一部に描く
（[../runtime/embedding.md](../runtime/embedding.md)）。
`PlatformScreen` をゲーム側で埋めることになる。

## 決めていないこと

- FreeType も `PlatformFont` も無いところで日本語を出す道
  （絵として貼る / 仮名だけの字形を内蔵する）。ブラウザは `PlatformFont` で片づいた
- X11 での変換つき入力（XIM）。いまは打った文字がそのまま入る
- 上の層の部品をどこまで増やすか（絵、入れ子の折りたたみ、表）。
  巻物は `ui.listbox`・`ui.textarea`・`ui.combo` の一覧が自分で持つ（帯・車輪・矢印）。
  **どんな部品でも包める入れ物としての巻物**は、まだ持たない
- 音。いまは持たない
