## ビルドと実行

```
make            # コア（静的な .o）と shark コマンドを作る
make test       # tests/ を走らせる（メモリの検査を含む）
make docs       # 標準ライブラリのリファレンス（docs/reference/）を作る
make docs-check # リファレンスに載る例を、ぜんぶ動かして確かめる
make embed      # 組み込みの例（examples/embed）を作る
make web        # ブラウザで動く形（WebAssembly）を作る
```

外部ライブラリは要らない。C++ コンパイラだけで通る。

```
./shark run examples/hello.shk      # 実行する
./shark check examples/fish.shk     # 型検査だけ
./shark test tests/unit_test.shk    # test_ で始まる関数を走らせる
./shark test                        # いまの場所の *_test.shk を全部（--filter 名前 で絞る）
./shark explain E0102               # エラーの詳しい説明
./shark modules                     # この処理系が持つモジュールの一覧
```

`--lang en` で診断を英語に、`--strict` で警告をエラーとして扱う。
`--memory <MB>` で使ってよいメモリの量を決める（既定は 64 MB、`0` で上限なし。下の[メモリの上限](#メモリの上限)）。

## 作ったもの

仕様どおり、**実行系（コア）** と **フロントエンド** を分けてある。

```
core/       実行系。ファイルも端末も触らない。ゲームに組み込む部品
frontend/   shark コマンド。ファイルを読み、コアを呼び、診断を端末向けに整形する
web/        ブラウザで動かす一式。コアを WebAssembly にして、画面から呼ぶ
```

`core/` はどのホストからも同じように使える。`frontend/main.cpp` は
「雛形をそのまま使ったときの参考実装」で、ゲーム本体も同じ立場になる
（[spec/frontend.md](../spec/frontend.md)）。

```
core/
  shark.h / shark.cpp     組み込みの入口（Engine）
  lexer   parser          字句解析・構文解析
  types   check           型と型検査
  codegen opcodes         バイトコード生成
  vm                      仮想マシン（タスクの切り替えを含む）
  value                   値・参照カウント・書き込み時コピー
  diag                    診断（番号と文面）
  registry                関数の表（標準ライブラリとホスト関数）
  prelude.h               Shark 自身で書いた部分（stdlib/prelude.shk から作る）
  platform/               移植層          ← 差し替える場所
    desktop.cpp             Windows / macOS / Linux
    console.cpp             ファイルも OS も無い機種の雛形
    web.cpp                 ブラウザ（WebAssembly）→ web/README.md
  lib/                    標準ライブラリ  ← ホスト関数を足す場所でもある
    builtin math time task fmt path file os text json test format
```

`host` という名前のファイルは作らず、**`Engine::register_host()`** に集めた
（[spec/runtime/embedding.md](../spec/runtime/embedding.md) の `register` にあたる）。
ゲーム側の関数はここに足す。

## 入っているもの

### 言語

| 仕様 | 実装 |
|---|---|
| 字句・コメント・数値／文字列／バイト列／f 文字列 | あり（入れ子コメント、`\u{...}` を含む） |
| `int` `float` `bool` `void` `string` `bytes` `list` `map` | あり（`int` は 64 ビット固定、あふれは実行時エラー） |
| 暗黙変換なし・`int(x)` などの明示変換 | あり |
| 型推論（宣言の行だけで完結） | あり |
| `T?` `none` `??` `if var` `!` `?.` | あり |
| `Result<T>` `Error` `try` `panic` | あり |
| クラス・継承・`virtual` / `override`・純粋仮想・インタフェース・`This` | あり |
| `Comparable` と `sort()` | あり（並べ替えは [stdlib/prelude.shk](../stdlib/prelude.shk) に Shark で書いてある） |
| ジェネリクス（関数・クラス・制約 `<T: Comparable>`） | あり（型ごとの複製はしない） |
| 関数オーバーロード（引数の型か個数で選ぶ） | あり |
| `ref`（引数だけ・借用） | あり |
| モジュール（`import`・`public`・相対パス・別名） | あり |
| `task` `parallel` `channel`・取り消し | あり（スレッドは使わない） |
| 書式指定 `f"{v:...}"` | あり（寄せ・ゼロ埋め・桁区切り・2/8/16 進・百分率） |
| ビット演算 `& \| ^ ~ << >>` と冪乗 `**` | あり（ビット演算は C と同じ結果・同じ強さ。`**` は右結合） |
| トップレベルに文を並べる書き方 | あり |

| `std.time` | あり | 暦の計算は自前。書式は `YYYY MM DD hh mm ss SSS` |
| `std.math` | あり | 乱数は xorshift を埋め込み。同じ種なら同じ並び |
| `std.task` | あり | `Task` `channel` `task.yield` `task.count` |
| `std.file` | あり | 移植層にファイル機能が無ければ登録しない |
| `std.path` | あり | |
| `std.text` | 一部 | 下の「入れていないもの」を見る |
| `std.fmt` | あり | |
| `std.json` | あり | |
| `std.os` | あり | `os.run` は移植層が持つときだけ |
| `std.crypto` | あり | ハッシュ（SHA-256/512、SHA-1、MD5、HMAC）は自前。乱数のもとは移植層から取り、真の乱数か安全な乱数かを `crypto.source()` が返す |
| `std.test` | あり | 1件ずつ順に走らせる |

### 実装での細かい決めごと

仕様が決めていないところを、実装として決めたもの。

| どこ | 決めごと |
|---|---|
| `os.run` | シェルを通さず直接起動する（引数の中身が命令として動かないように）。`*` の展開や `\|` は行われない。標準エラー出力も取れる |
| `file.File.read(n)` | 一度に読むのは 1 GB まで。負の数は空のバイト列 |
| `json.parse` | 入れ子は 200 段まで。`\uD83D\uDE00` のようなサロゲート対は1文字にまとめる |
| `text.regex` | 照合の深さは 4000 まで。`a*` `[0-9]+` のような1文字の繰り返しは深さを使わない |
| `map` | 要素が 8 個を超えたら索引（開番地法）を作る。反復の順は挿入順のまま |
| 呼び出しの深さ | 既定 10,000（`Config::max_call_depth`）。超えたら実行時エラー |
| 値の置き場 | main は 65,536 個、タスクは 4,096 個（`Config::stack_size` / `task_stack_size`）。走っている間のメモリとして数える |
| 書式指定 | 小数点以下は 17 桁まで。int に収まらない大きさは `1e+30` のように書く |
| ずらす幅 | `<<` `>>` の右は 0 〜 63。外は実行時エラー（C では未定義のところ）。`<<` ではみ出した桁は落とし、あふれとして止めない |
| `>>` | 符号を保つ（算術シフト）。C では処理系まかせのところを決めてある |
| `**` | `int` は繰り返し二乗で計算し、あふれたら実行時エラー。指数が負なら実行時エラー。`0 ** 0` は `1`。`float` は `pow()` |
| `float` の表示 | 元に戻る一番短い桁数で書く。10^-4 〜 10^15 の間は小数の形（`60.0`）、外は指数の形（`1e+16`） |
| `float` の読み取り | 64 ビット整数にためてから 10 のべき乗で寄せる。`10^22` までは1回の掛け算・割り算で誤差なく、それ以外は 22 桁ずつ寄せる（有効数字 16 桁を超えると 1 ulp ずれることがある） |
| `Time` | 瞬間は常に UTC で持ち、`to_local()` / `to_utc()` は**表示のずれだけ**を付け替える。足し引きしても、その表示は引き継ぐ |
| `?.` の先 | `xs?.push(...)` のように中身を書き換えるメソッドは呼べない（E0211）。取り出せるのはコピーなので |
| クラス | 自分自身を値として持てない（E0409）。`Node?` か `list<Node>` にする |

## 入れていないもの

[spec/skeleton.md](../spec/skeleton.md) の「Shark と名乗る条件」3 に従って、削ったものを書いておく。

| 削ったもの | 理由・代わり |
|---|---|
| `std.net` `std.http` | 移植層のノンブロッキング通信から作る必要がある。`import` すると E0501 が返る |
| `std.ui` | 画面の実装が要る。GUI はホスト側で用意して `register_host` で渡す形にしてある |
| 実行時コンパイル（JIT） | 仕様でも任意機能。いまは常に仮想マシンで実行する。結果は変わらない |
| `shark build` / `.shkc` | バイトコードの保存と読み込み。形式は変えてよい決まりなので後回しにした |
| `shark fmt` | 整形の規則がまだ決まっていない（[spec/open-questions.md](../spec/open-questions.md)） |
| 言語サーバ | 同上。`shark check` の出力をそのまま使う形にしてある |
| `std.text` の一部 | 正規化は仮名の濁点の合成・分解だけ。文字コード変換は `utf-8` のみ（それ以外は失敗を返す） |
| 複数スレッドへの割り振り | 仕様どおり既定の1本のまま |

正規表現は入っている（文字クラス、`* + ? { }`、`|`、`( )`、`^ $`）。先読みと後方参照は持たない。

## ゲームに組み込む

動く例が [examples/embed/game.cpp](../examples/embed/game.cpp) にある（`make embed`）。

```cpp
Config cfg;
cfg.with_file = false;          // 機種に無いモジュールは入れない
Engine engine(cfg);

// ゲーム側の操作を足す（これがそのままプレイヤーのコードから呼べる）
TypeTable& t = engine.types();
engine.register_host("move", h_move, t.t_void(), t.t_string());

// print の行き先を決める
HostIO io;
io.write_out = on_output;
engine.set_io(io);

// ソースは文字列で渡す。コアはファイルを開かない
const Vec<Diagnostic>& ds = engine.load(Str("ステージ3"), Str(player_code));

// 毎フレーム、決めた命令数だけ進める
for (;;) {
  RunStatus st = engine.step(60);
  if (st != SK_Running) break;
  draw_frame();                 // 無限ループを書かれても、ここに戻ってくる
}
```

- プレイヤーに渡す関数の一覧も同じ道具で作れる。ゲーム側の関数を `.shk` の宣言ファイルに
  書いて `python3 docs/gen.py out --stdlib その置き場` を走らせる（[stdlib/README.md](../stdlib/README.md)）
- `step(budget)` の `budget` は**命令の数**。時間ではないので、機種や負荷で結果が変わらない
- 止めたいときは `engine.abort_run()`
- 診断は構造化データ（`Diagnostic`）で返る。整形はホストの仕事。
  端末向けの整形例として `format_diagnostic()` を置いてある

## 新しい機種に移植する

`core/platform/` に1つ足して、そこだけ書けば動く。

1. `core/platform/console.cpp` を複製する（必須の4つだけが並んでいる）
2. メモリ・時間・標準入出力・終了を埋める
3. 使えるならファイル（`PlatformFile`）と OS（`PlatformOS`）も埋める。要らなければ `0` のまま
4. ホストの最初に `platform_set(platform_自分の機種());` を呼ぶ

必須の4つだけでも、`time` `math` `task` と言語のすべてが動く。
`file` や `os` を持たない移植層では、対応するモジュールは登録されず、
`import` した時点で E0501 が返る（実行してから失敗するのではない）。

実際に足した例が [core/platform/web.cpp](../core/platform/web.cpp)（ブラウザ）。
コアには手を入れていない。待てない環境なので `sleep` は何もせず、
進む量はホストが `step()` の刻みで決める（[web/README.md](../web/README.md)）。

### まだ入力が無いとき

端末は `read` の中で待てるが、ブラウザやゲームは止まって待てない。
そこで `HostIO` に「行が来ているか」を尋ねる口（`input_ready`）を1つ置いた。

| ホスト | どうなるか |
|---|---|
| 口を出さない（`shark` コマンド） | `input()` はその場で読む。いままでどおり |
| 「まだ」と答える（ブラウザ） | `input()` は待ちに入り、`step()` はホストに返る。`Engine::waiting_input()` が立つ |
| 「終端」と答える | `input()` は `none` |

待ちに入っている間も他のタスクは動く。行き詰まり（deadlock）とは区別していて、
入力待ちのときは実行時エラーにしない（[../core/vm.cpp](../core/vm.cpp)）。

## メモリの上限

**プログラムを動かすときに使ってよいメモリの量を決めておき、超えたら実行時エラーで止める。**
決めごとは [spec/runtime/memory.md](../spec/runtime/memory.md) の「使いすぎたとき」と
[spec/runtime/embedding.md](../spec/runtime/embedding.md) の「使ってよいメモリの量を決める」にある。
ここでは実装の側を書く。

ゲーム機では確保に失敗してから何かをするのは難しく、
言語じたいが例外を持たないので、確保の失敗を途中で受け止める道も無い。
そこで「失敗してから対処する」のではなく、**先に上限を決めて、超えたら止める**ことにした。

### 決め方

| 使う側 | 書き方 | 既定 |
|---|---|---|
| 組み込み | `Config::memory_limit`（バイト。`0` は上限なし） | 64 MB |
| `shark` コマンド | `--memory <MB>`（`0` は上限なし） | 64 MB |

上限は**確保の口ごと**なので、1つのプロセスに1つ。

| 取り出す | 何が返るか |
|---|---|
| `Engine::memory_used()` | いま動いているプログラムが使っている量（上限が掛かるのはこちら） |
| `Engine::memory_total()` | 読み込みで作ったもの（構文木・バイトコード・型の表）も含む全体 |

### 数え方

コアの確保はすべて `sk_alloc` / `sk_realloc` / `sk_free`（`core/support.cpp`）を通る。
塊の先頭に「大きさ」と「どの区分か」を置いておき、区分ごとに合計を持つ。

- 区分は `sk_mem_set_phase()` で切り替える。`VM::step()` と `VM::start()` の間だけ「実行中」
- そのため、**実行中に作った値・タスクの値スタック・標準ライブラリが作る文字列**が数に入り、
  構文木やバイトコード、定数、型の表は入らない
- 区分は塊ごとに覚えてあるので、解放が実行中でなくても正しい方から引かれる

20000 行のプログラムで測ると、読み込みに 20 MB 使っても、
実行中のぶんは 0.13 MB（ほぼタスクの値スタック）だった。
上限 1 MB のままでも、読み込みも実行も通る。

### 超えたときの動き

**確保そのものは断らない。**断ってしまうと、例外の無いこの実装では
その場で書き換えのしようがなく、落とすしかなくなるため。
代わりに「超えている」状態にして、次の区切りで止める。

| いつ | どうなる |
|---|---|
| 実行中 | 命令の切れ目で `panic` になる。抱えていた値はその場で離すので、使用量は元に戻る |
| タスクの中 | そのタスクだけが止まる。`wait()` で受け取ったときにエラーとして返る |
| 移植層の確保そのものが失敗 | もう続けられないので `platform().fatal` |

```
panic: メモリを使いすぎました
  上限は 8 MB です。増え続ける配列や文字列がないか見てください
  --> main.shk:5
  呼び出しの経路:
    main.shk:5  main
```

区切りごとに見るので、**上限を少し超えてから止まる**。
1回の確保が大きいとき（文字列を倍々に伸ばすなど）ほど超える量は大きい。
`tests/memcheck.cpp` は、山が上限の2倍未満に収まることを毎回確かめている。

### 後始末の検査

参照カウントの取りこぼしがあると、上限だけでは守り切れない。
そこで `tests/memcheck.cpp`（`make test` に入っている）が、
処理系を捨てたあとに**確保した量が 0 に戻るか**を毎回見ている。
値・クラス・タスク・チャネル・`Result`・実行時エラーで止まった後・読み込み直し、
それぞれで 0 に戻ることと、**読み込みのぶんが上限の対象になっていないこと**を確かめる。

## 中身の作り

### 値（core/value.h）

- `int` `float` `bool` は実体をそのまま持つ。それ以外は参照カウント付きの実体を指す
- **代入はコピー**。実装は共有＋参照数の加算で、**書き込むときに参照数が2以上なら複製する**
- 参照カウントだけで足りる（代入がコピーなので循環が作れない）。ごみ集めは持たない
- 片付けは**繰り返し**で行う。`Node?` を数十万段つないだ鎖でも、
  C++ の再帰にならないよう、片付け待ちを並べて順に処理する
- ハンドル型（`File` `Task` `channel`）だけは複製しない。コピーしても同じ実体を指す
- `ref` は内部で「借用（`V_Ref`）」として渡す。引数の間だけ生き、返すことも保存することもできない

メソッドの受け手も、変数に対して呼んだときは借用で渡している。
そのため `b.rename()` は `b` の側だけを書き換え、`a = b` の元は変わらない
（書き込みの直前に複製されるため）。

`map` は、**挿入した順の並び**と、**引くための索引**（開番地法）を分けて持つ。
反復の順は仕様どおり挿入順のまま、`m[k]` は要素数によらず一定の速さで引ける
（索引は要素が 8 個を超えたところで作る）。

### 仮想マシン（core/vm.cpp）

- スタック型。命令コードは1バイト、オペランドは 4 バイト
- 局所変数は値スタックの上に置く（フレームごとの `base` で区切る）
- 代入先は「place」として持つ。`xs[i].name = v` のような形でも、
  途中で必要な複製がその場で起きる
- `virtual` はクラスごとのメソッド表（vtable）。表の位置は
  **同じ名前・同じ引数なら、どのクラスでも同じ番号**になるように決めている。
  インタフェースを実装したクラス同士で番号が揃うので、`This` を使った `compare` も同じ仕組みで呼べる

### タスク（core/vm.cpp、core/lib/task.cpp）

- タスクごとに値スタックとフレームを持つ。OS のスレッドは使わない
- 待つ関数は「まだ終わらない（`N_Wait`）」を返し、次の刻みで**同じ引数のまま呼び直される**。
  `sleep` は起床時刻を持ち、`recv` などは条件が満たされるまで何度も呼ばれる
- 取り消しは要求を立てるだけ。待つ関数が要求を見て、その場でタスクを終える
- どのタスクも進めない状態が続いたら、時計を持つタスクがあれば「待ち」として
  ホストに戻り、無ければ「すべてのタスクが待ったままになりました」と止める

### 診断（core/diag.h）

- コアは**文字を整形しない**。`severity` `code` `message` `spans` `help` を返すだけ
- 文面は日本語と英語を持ち、`Config::lang` で選ぶ
- 番号は仕様の表（E0101 / E0102 / …）に合わせてある。`shark explain E0102` で詳しい説明が出る

## 仕様に無い足しもの

[spec/](../spec/) に書かれていないが、実装で足したもの。
構文と型の規則は変えていない（[spec/skeleton.md](../spec/skeleton.md) の「してはいけないこと」）。

| 足したもの | なぜ |
|---|---|
| `print` が `list` と `map` も受け取る | 学習中に中身を見る場面が多いため（オーバーロードを増やしただけ） |

メモリの上限も最初は仕様書の外で足したが、いまは仕様に入れてある
（[spec/runtime/memory.md](../spec/runtime/memory.md)）。

## 速さ

C・Python と同じ内容を書いて測ったものを [../README.md](../README.md) の「速さ」に載せてある。
測るものは [../bench/](../bench/) にあり、`make bench` で測り直せる。

いまの位置づけはこう。

| | |
|---|---|
| ループ・配列・key-value | Python より速い |
| 関数呼び出し（`fib`）・文字列づくり | Python より遅い |
| 最適化した C | 5〜60 倍の差 |

関数呼び出しが遅いのは、呼ぶたびに枠（フレーム）を積み、局所変数のぶんを
値スタックに用意しているため。実行時コンパイル（JIT）は仕様でも任意機能なので、
いまは仮想マシンだけで動かしている（[入れていないもの](#入れていないもの)）。

## 決めていなかったことへの答え

[spec/open-questions.md](../spec/open-questions.md) のうち、実装で決まったもの。

| # | 決めたこと |
|---|---|
| 2 | 実行時コンパイルは入れていないので、しきい値も無い（仮想マシンだけで動く） |
| 3 | 埋め込んだ Unicode の表は仮名の並び順（83 文字ぶん）と表示幅の範囲だけ。数百バイトに収まっている |
| 4 | **C++17** に合わせた。例外と RTTI は使わない（`-fno-exceptions -fno-rtti`）。標準ライブラリは `<stdint.h>` `<new>` などの薄い範囲と、数の書き出しに使う `snprintf`、`std.math` の `<math.h>` だけ |
| 5 | ホスト関数に渡せるのは基本型とコレクションのまま |
| 6 | 実行の途中状態の保存は入れていない |

残り（GUI の既定値、言語サーバ、整形規則、配り方）は手を付けていない。
